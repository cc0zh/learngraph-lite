# 求职作品的最小完整形态

**状态：2026-10-17 产品边界与阶段决定。** 原稿仅供讨论；用户后续已授权第一轮“开始—继续—清理”闭环实施，具体边界见[执行计划](../exec-plans/active/product-learning-experience.md)。学习包形态和最终求职交付仍待后续完成，不将整份候选清单视为实施授权。沿用现有知识地图与节点学习方向；不另选业务、不重建仓库、不要求对齐原版全部能力。关联[产品原则](../PRODUCT_SENSE.md)与[原始规格](../从零构建功能文档.md)。

## 1. 先回到任务本身

要交付的是一个能用于初级 Agent / AI 应用开发求职、用户自己能解释的作品，不是一个功能齐全的商业教育平台，也不是 Agent 基础设施展示台。

最小产品仍是：**用知识地图组织一个学习主题，围绕节点探索，并能继续使用、整理和管理相关对话与学习内容的本地单用户应用。**

作品完成需要三件事同时成立：

1. 产品主线合理，能正常开始、使用、继续和清理，不只跑通生成流程。
2. Agent 在其中有真实职责，模型、工具、确定性业务规则与用户决定的边界讲得通。
3. 项目拥有者能解释核心调用链、设计取舍、AI 辅助与个人贡献，不只复述包装文案。

Lite 应轻在依赖、部署与非必要系统复杂度，而不是省掉基本产品完整性。已有工程治理是底座，不能代替学习体验，也不因本轮转回产品讨论就删除。

## 2. 当前判断依据

- **已有工程能力：**图谱草稿和发布、节点独立会话、节点内容持久化、资料检索引用、固定组件学习包、正式练习与确定性判分、取消和显式恢复。机制见[核心说明](../core/index.md)。
- **已观察的页面事实：**一张图谱、一个节点可完成讲解、教材、资料追问、一道作答和返回；不证明所有模块有足够价值，更不证明产品已完整。方法与覆盖边界见[走查](../demo/personal-learning-experience-review.md)。
- **后续用户反馈：**开始前配置感重，会话和图谱不能删除，学习包相较原版显得鸡肋。当前学习空间目录代码也未提供整条会话/整张图谱的删除入口；草稿“删除节点”不是这两项能力。本轮不据此断言所有后端接口均无删除能力，也不展开 Bug 调查。
- **尚未证明：**用户真实学习收益、当前学习包的独立价值、与原版的同条件体验差异。原规格第 16 节是历史源码核查，不是本轮原版运行结果。

## 3. 最小完整主线

```text
提出一个学习主题
  → 看懂并确认知识结构
  → 选择关心的节点，自由学习和追问
  → 按需要使用资料、教材或练习
  → 回来继续已有内容
  → 整理、放弃或删除不再需要的内容
```

图谱是主题组织的核心，不是聊天旁的装饰。资料上传、教材生成和练习是可选支线，不是开始学习的前置配置清单。保留目标确认与图谱发布的决定边界，但不要求用户为了操作系统而理解每个内部状态。

用户主要需要理解“学习主题/图谱—知识节点—相关对话与内容”这层关系；不需要先掌握目标、run、ACK、slot、修订等内部概念。这里是界面组织建议，不要求改名或重写领域模型。

## 4. 模块取舍建议

| 模块 | 在作品中的地位 | 最小边界 |
| --- | --- | --- |
| 知识图谱 | 核心 | 有助于理解范围和关系，能进入节点；不退化成目录列表，也不追求复杂关系本体 |
| 节点对话 | 核心 | 学习范围清楚；新对话和继续历史不同；不自动混合其他聊天 |
| 节点学习内容 | 核心能力，当前价值需补证 | 留下实际有用、可继续读和局部追问的内容，不以多生成几类卡片作为完成标准 |
| 会话/图谱管理 | 最低完整性 | 至少能删除无用会话、放弃或删除不再需要的主题/图谱；不是仅生成和永久堆积 |
| 资料与引用 | 重要辅助 | 有资料时可真正使用，范围透明；无资料也能开始，不强迫先配置全套绑定 |
| 正式练习与反馈 | 保留但按需 | 程序判分和记录，帮助自查；不作为所有节点的必经关卡或能力认证 |
| 独立“学习包”产品形态 | 不默认视为亮点，需收敛 | 已有工程实现保留；是否需要一个独立包入口、怎样组织内容，取决于具体价值而非旧名称 |
| 普通聊天 | 辅助入口 | 可以存在，不再建设成另一款通用聊天产品，也不能抢走知识地图主线 |
| 运行、版本与恢复 | 支撑底座 | 保留正确性与可观测性；不继续扩成企业治理平台或让学习者操作内部任务身份 |

删除能力是基本使用权，不是求职的技术亮点。第一轮采用删除会话不连带抹掉共享节点教材和成绩、删除主题明确清理其专属记录、独立上传资料保留的语义；不自动清理现有用户数据，只在隔离测试库中验收。不以归档偷偷替代删除，也不趁机扩展回收站、批量管理或全实体 CRUD 平台。

## 5. 学习包必须正面处理，不能靠改名过关

原规格第 8 节明确将自由 HTML/代码生成收窄为 Markdown 和固定组件。这是能力边界的有意改变，不是原版教学体验已经被等价保留的证据。限制执行范围有工程理由，但不能替“教学内容是否有用”作答。

建议保留节点教材、局部追问和可选练习，不把独立学习包做成学习前必生成的整套课件，也不因已经实现就要求每个主题凑齐章节、题卡、步骤和表格。

最小有效内容至少应针对一个具体难点，体现聊天长文本之外的作用，例如把两个概念放在同一视图比较、呈现一个过程的关键变化，并能针对当前部分追问。**只有“下一步”按钮或把同一段聊天换页，不足以称为交互教学亮点。** 当前学习包是否达到这个标准仍未证明，不把用户不认可的体验写成已完成价值。

首版不承诺原版级自由互动课件。若它确实是要保留的核心体验，应先定义一个具体、有实质交互的教学任务，再决定固定组件是否够用、是否需要扩展；不能默认恢复任意 HTML/JS 执行，也不能默认删除整套学习页。原 P1 的受控交互页要求并未被这份讨论稿取消。

## 6. 作为求职作品，哪些是必须补齐的

建议围绕三个产品级交付包收敛，而不是逐项追修页面细节：

1. **可管理的学习空间：**建立清楚的主题、节点、会话与内容归属，补基本删除/放弃能力，使持续积累不变成只能增长的垃圾堆。
2. **自然的学习主线：**从意图到图谱再到节点学习连续可理解，资料和教材按需加入，保留用户确认而减少独立配置任务。
3. **有明确作用的节点内容：**选一个代表性节点证明教材与局部交互的用途；不能用“schema 通过、四组件齐全”代替可用性，也不先承诺大规模追平原版。

第一轮实施前两项；第三项先以具体样例决定后续范围，不在本轮重建学习包。完成第一轮后就可开始整理能真实展示主线、取舍与限制的短演示，以及项目拥有者能讲清的三条链路：规划与确认、节点模型—工具调用、内容/作答如何保存并再次使用。演示不是强制用户学习流程，也不要求每次使用都展示全部模块。

暂不扩展认证、多用户、长期记忆、多 Agent、向量检索、任意代码执行、提醒系统或更多组件数量。内容可信度按用户要求暂不作为本轮建设主线，但既有失败仍留[质量记录](../QUALITY_SCORE.md)，不能宣称已解决。

## 7. 已确认与后续边界

- 已采用现有方向的最小边界，并授权第一轮学习主线与生命周期实施；不是重新选择产品方向。
- 学习包在代表节点中要提供的具体价值，以及独立包形态的保留/调整范围；不能由助手擅自删掉或全面重建。
- 第一轮删除语义与本轮文件分工已落实到执行计划；此前其他会话改动保留，不覆盖，现有日常数据库不操作。

原讨论阶段只完成边界判断与纠偏；后续实施与验收以执行计划为准。本轮不新增真实模型调用，不将尚未验证的教学效果、学习包价值或本人讲解能力写成完成。

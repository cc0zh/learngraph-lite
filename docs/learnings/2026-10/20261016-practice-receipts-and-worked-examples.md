# 正式练习隔离不只是隐藏答案键

一次真实教学先解释了数值、负索引和切片结果，再给出了使用相同数据的单选题。系统没有把私有答案键发给模型，仍然提前给出了足够确定选项的信息。

## 两个方向的数据要分开

- **进入出题器**：提供宿主已见的讲解文本，明确哪些例子已经解过。它是业务数据，不是允许改写系统指令的文本；限制范围和字节数，避免混入其他会话与预算失控。
- **回到教学模型**：成功后只给题目 ID 回执，不回注新题干/选项。题目依旧进入公共 output 与 UI，不是为了防泄漏删除产品能力；其他工具仍可用 ID 组合学习包。

如果让模型先演示、工具生成、最后只确认保存，别忘了原 Runner 常常只把最后一条回复作为 final_text。保留工具前文本必须只包含本轮 assistant 正文，不拼回历史，也不把私有生成器的修复对话混进去；SSE 终态和 SQLite 重开都要验证。

## 机械保证与模型判断的边界

归一化题干包含检查能拒绝精确重复，无法判断换变量名、组合几条表达式后的等价解答。上下文和提示约束是改进，不是通用语义证明；应保留真实人工走查，不能把离线通过写成默认不泄漏答案通过。

知识错误也要区分值与身份。例如 list 切片是新的浅拷贝，tuple 的完整切片却不保证新对象；CPython 可返回同一个普通 tuple。固定参考代码用于反驳错误绝对命题，不执行模型生成代码，也不把某一实现行为扩展为所有语言实现的保证。

# 引用编号为什么属于一轮回答

`C1` 的含义是“本轮第一个来源”，不是全局文档 ID。模型应使用服务端从实际检索结果分配的编号，原文链接用 `run_id + citation_id` 定位。若直接接受模型给出的文档路径或 chunk ID，就无法证明那是本轮看到的依据。

多次检索可能返回同一个片段，复用编号能避免 C1/C2 指向相同内容。内容、版本或位置变化时必须产生新来源，不能因为 chunk ID 没变而静默改写旧 C1。保存版本、片段内容摘要值和引用位置，能够在同版本覆盖或重新分块时发现旧来源已经失效。

有两个检查时点：完成时生成来源快照，点击时再读当前绑定与内容。完成快照回答“生成时是否可定位”，点击检查回答“现在还能否打开这份原文”。解绑后，旧回答仍可保留文本和来源记录，但不应继续返回原文。取消与结果投影也会竞争：来源校验应在终态锁外运行，写入时再检查终态，避免慢数据库读取阻塞取消或晚结果覆盖取消。

最容易混淆的是来源有效性与语义支持。合法 C1 只证明来源确实返回过且可定位；模型仍可能从它推出不支持的结论。未知编号不能点击，但“所有编号都合法”仍不足以作为 grounding 评估。语义支持要用问题、原文和回答一起评估。

自检：两轮回答都有 C1，它们能共享链接吗？同一 chunk ID 内容被覆盖，旧回答应该打开新内容吗？引用有效能否证明模型没有幻觉？对应实现与验收见 [执行计划](../../exec-plans/active/learngraph-lite-implementation.md)。

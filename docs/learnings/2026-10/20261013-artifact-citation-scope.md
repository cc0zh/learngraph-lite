# C1 的含义取决于产物来源表

回答和练习都出现 `[C1]`，并不意味着引用同一份资料。回答先检索 beta，练习按节点学习结果检索 alpha，两次检索的第一个结果都是 C1。若 UI 用回答来源表解析题目 C1，点击会跳到错误原文，即使两个 ID 都存在。

## 存标签不够，必须存映射

来源键实际是 `(产物作用域, citation_id)`。回答用 run_id，题目用 exercise_id，当前图谱用 goal_id + planning version。来源表保存 document/chunk ID、资料版本、原文位置和内容 hash；每项 citation_ids 表示它用了哪些来源。模型选择已有编号，服务端建立映射，避免模型自己编造原文坐标。

生成与一次 repair 使用同一来源表，否则修复时的 C1 可能换义。每题保存自己的表，教学工具返回题目表时也不应把它合并进回答表。来源原文进入模型上下文才有 grounding 的数据基础；仅关联 document_id 无法证明模型读过资料。

## 来源真实与内容受支持是两种检查

程序可以检查 ID、显式绑定、版本/hash/offset，以及正文引用是否列入 citation_ids。它不能由这些条件证明“原文支持这个结论”。资料讲保存偏移，模型引用它来断言某个数据库性能最好，引用仍可能全部通过存在性检查；需要另做人工或语义评估。

人工改写也是同样的边界：清空表会让保留的 `[C1]` 无法定位，保留 documents 声明又可能夸大来源支持。这里保留表并标 edited，让原文可查、生成声明可区分；仍拒绝编辑新增的未知编号。source_mode 表示生成方式，status 表示当前来源可用性，二者不能替代内容支持评估。

自检：看到 C1 时，是否知道它属于哪项产物？删除资料后，是否仍把保存时的 valid 当成当前状态？测试证据证明的是来源边界，还是模型结论被原文支持？

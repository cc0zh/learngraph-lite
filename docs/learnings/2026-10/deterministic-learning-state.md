# 学习状态不要交给模型判定

## 是什么

LearnGraph Lite 的练习得分、掌握度和下一步推荐采用确定性领域规则，而不是让模型直接决定用户是否掌握。模型可以生成讲解和题目草稿，但正式作答由服务端比对私有答案，推荐由前置依赖、近期错题和时间预算计算。

## 为什么需要

如果让模型在对话里直接宣布“已掌握”，刷新、重试、换模型或提示词变化都会影响业务状态。简历作品可以不做企业级权限平台，但核心学习证据必须可审核：同一道题是否首次计分、答案是否正确、为什么推荐某个节点，都应能从数据结构和规则复现。

## 怎么想

- Public DTO 只给题目、选项、节点和版本，不给标准答案。
- Private 题目保存 correct_option_id、解析和归一化哈希。
- Attempt 保存服务端判分结果和 counted 标记；同题重答可反馈，但不重复计入统计。
- Mastery 只看近期最多五道不同题的有效首次作答。
- Recommendation 先筛前置依赖已满足的节点，再根据错题和时间预算排序。

## 常见陷阱

- 换一个 exercise_id 复用同一题干和选项，会污染掌握度，所以要做完全重复题哈希。
- 阅读完成、点击节点和学习时长不能直接提升掌握度。
- 新题答错必须能让状态下降，否则会退回“星级只增不减”的旧规则。
- 解释文案可以交给模型润色，但 reason_codes、node_id、graph_revision 应由服务端产生。

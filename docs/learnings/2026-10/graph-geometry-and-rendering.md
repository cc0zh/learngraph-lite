# 固定尺寸图节点：CSS 尺寸不等于画布几何

图谱看起来空白，不一定是没有数据。还应检查：节点是否存在于 DOM、是否停在 `visibility: hidden`、布局器与画布是否已经拿到相同的节点尺寸。

## 两份几何必须一致

使用 Dagre 排列节点，再交给 React Flow 绘制时，至少有两份几何信息：

- 布局器用宽高计算节点的位置与边。
- 画布用宽高计算包围盒、可见范围和 `fitView`。

即使 CSS 已设置 `width` 和 `height`，画布仍可能需要经过 DOM 测量才能得到内部尺寸。在隐藏区域、响应式切换和快速挂载过程中，这个测量时序不应成为固定尺寸节点能否显示的必要条件。

```tsx
// 不充分：布局器知道尺寸，画布节点模型仍需要测量。
layout.setNode(id, { width: 160, height: 54 });
const node = { id, position, data, style: { width: 160, height: 54 } };

// 固定尺寸时：显式向画布提供同一份几何。
const node = { id, width: 160, height: 54, position, data };
```

这不是通用的“加上宽高就好”。如果内容会撑高节点，就应保留测量，并在测量结果变化后更新布局；不能为了通过检查，把可变内容硬塞进固定盒子。

## 如何验证修复是真的

只检查 `.react-flow__node` 数量不够：隐藏节点也计数。只检查截图请求结束也不够：网络空闲不代表布局与画布已经就绪。

应当同时验证：

- 节点的计算样式不是 `visibility: hidden`。
- 节点的实际包围盒与画布相交。
- 从桌面切到平板、手机，并经过工具页和会话导航后依然成立。
- 检查时只导航与读取，不顺便创建学习任务。

本次重构的七节点截图序列在平板状态复现了“DOM 有七个节点，但节点仍不可见”；显式几何后，三个宽度的十八张截图均完成，浏览器没有页面异常。回归入口为 `frontend/tests/taste-studio.spec.ts` 的 `overview nodes paint` 用例。

可迁移的原则是：**数据就绪、DOM 存在、几何就绪和用户可见，是四件不同的事。** 图表、编辑器和虚拟列表的验收都应覆盖最后一层。

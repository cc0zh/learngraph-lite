# 会话边界和学习积累为什么不能用同一个 ID

## 一句话区分

会话回答“这次交流说了什么”，节点回答“这个知识点积累了什么”。把两者都用 `(goal,node)` 标识，会让“重新开始聊天”变成继续同一段历史；反过来把所有东西都放进 session，又会让教材和成绩随聊天消失。

## 用三个身份思考

| 身份 | 负责什么 | 重开聊天时 |
| --- | --- | --- |
| 节点 | 知识内容、教材、题目、成绩 | 共享 |
| 会话 | 明确模式、固定图谱/节点、独立 transcript | 新建 |
| 运行 | 一次授权请求、结果与失败重试 | 独立管理 |

界面统一，不意味着这些边界也合并。右侧浏览节点只是选择预览；只有新会话或显式恢复才确定本次交流范围。服务端同样检查元数据，不能只相信前端标题。

## 创建为什么也需要幂等身份

如果先 POST 创建、再把服务端生成的 ID 记在浏览器，响应丢失时客户端甚至不知道该查哪一个目标。先生成并保存客户端 ID，再发送；服务端把创建指纹与数据同事务保存，就能明确区分“同一操作恢复”和“借旧 ID 改输入”。

创建对象与开始模型调用是两次授权步骤：创建记录成功不代表首轮 run 成功。两者分别保存身份，刷新只读取，显式继续才重发原命令。等待响应期间的新草稿也不能被旧成功清空。

## 一个容易漏掉的共享事件陷阱

教材步骤事件可共享，但解释任务可能按 `(event,slot)` 去重，并不包含 session。新会话若仍用固定 `initial` slot，会撞上旧解释的业务键。每条会话保存独立初始 slot；网络恢复复用它，只有“重新解释”才换 slot。不要把“按会话隔离”误认为换一个 session 参数就足够。

## 自检

1. 刷新、切换节点或打开已创建的空会话，会不会暗中开始模型调用？
2. 首轮被拒绝、创建响应丢失、用户已输入新草稿，三种情况是否各有恢复路径？
3. 两条会话看到同一份教材时，是否意外共享了聊天历史或解释幂等键？

# 固定视口工作台：横向不溢出，不代表内容可达

## 问题是什么

三栏应用常用 `height:100dvh; overflow:hidden` 固定根，再让各栏内部滚动。这能把目录、阅读和图谱留在各自位置，但前提是顶部导航及上下文区域没有吃掉整个屏幕。

本次把文字、按钮调整到可读和可触控的尺寸后，375px 宽的常规手机看起来正常，568×320 横屏却出现输入框不能完整进入视口的问题。

## 为什么 minmax(0, 1fr) 没能救它

可以把三行布局想成：

```text
固定视口高度
  - 顶部品牌栏
  - 自动高度的上下文信息
  - 自动高度的手机区域导航
  = 留给内容区的高度
```

`minmax(0, 1fr)` 允许内容行收缩到零。它防止内容撑破网格，却不保证读者还能看到这一行。再加上根容器裁切，内部滚动只能移动栏里的内容，不能把整栏移回屏幕。

长会话名、浏览器缩放、横屏和虚拟键盘都会放大这个问题。不能只检查 `scrollWidth <= innerWidth`。

## 修法：空间不足时换滚动责任

正常桌面保留固定视口和分栏滚动；短屏切换为页面纵向滚动，让顶部和正文能一起离开或进入视口。

```css
@media (max-height: 600px) {
  #root:has(.workbench) {
    height: auto;
    min-height: 100dvh;
    overflow: visible;
  }
  .workbench {
    height: auto;
    grid-template-rows: auto minmax(360px, auto);
  }
}
```

手机多一行区域导航，需要对应的三行定义。这里的 600px / 360px 是当前内容密度下的策略值，不是通用标准。`dvh` 可以响应动态视口，但各移动浏览器虚拟键盘的行为仍需真机验证。

不要通过缩小文字、把按钮压到无法触控、裁掉会话范围或藏起错误来解决高度问题。

## 怎么测试才有意义

- 构造长标题/会话名，覆盖宽度 **和高度**。
- `toBeVisible()` 只说明元素有可见样式和尺寸，不保证它处在可点击视口。
- 让测试滚动到输入框并实际点击、聚焦、填写，再检查 `boundingBox().y + height <= viewport.height`。
- 保留请求观察：为了修布局，不应让切换区域、滚动或刷新顺便触发模型 POST。
- 留一张聚焦后的短屏截图，核对输入框、焦点环和发送操作确实可达。

# 测 Agent 时，不要把答案写进用户问题

“务必调用 create_exercise，count=1，别透露答案”可以测工具协议，却测不了普通学习者会不会得到合适的练习：测试作者已经替 Agent 做出了关键决策，还替产品补了一条安全提醒。

## 把输入与断言的职责分开

| 位置 | 应放什么 |
| --- | --- |
| 用户输入 | 想学什么、哪里不懂、希望怎样练习 |
| 系统与工具说明 | 可用操作、参数契约、安全与人工确认边界 |
| 测试断言 | 本轮工具执行成功、新产物已保存、用户操作前状态未被擅自推进 |

自然输入可以是“能举个简单例子，再出一道单选练习让我试试吗？”工具名字并没有消失，而是回到测试侧检查活动记录；不能只看助手说“出好了”，也不能仅看页面上恰好有一道旧题。

可靠的检查顺序：记住旧题 ID → 发送自然需求 → 核对本轮工具 completed → 核对本轮输出 ID 恰好对应新增保存题目。题目公共字段没有答案是结构隔离；回复没暗示答案是语义行为，两种证据不能互相代替。

## 三类证据不要混用

- **协议 smoke**：明确要求 echo 或指定调用顺序，验证供应商和编排契约，合理但范围有限。
- **用户旅程**：使用自然需求，由模型决定行动，结合持久状态证明结果。
- **语义评估**：检查准确性、必要先修、泄漏和支持程度，需要更多样本及明确评分规则。

fixture 可以让用户旅程的界面和状态测试稳定，但模型行为已预定，所以输入改自然、离线测试变绿，也不意味着真实模型已通过自主决策验收。事后修正输入不能追溯升级旧证据，应保留原结果并重新限定结论。

实例见[本次审查计划](../../exec-plans/completed/natural-user-input-audit.md)。

## 实际复验的反例

后续[自然输入真实复验](../../exec-plans/completed/natural-real-workbench-smoke.md)工具路由、持久化和恢复断言全部通过，但模型先列出同数值同表达式的运算结果，再把它们拼成待答题。它既没有读取私有答案，也没有说“正确选项是 A”，仍足以提前提示答案。由此应分别维护：链路是否完成、公共字段是否隔离、讲解是否给出待测题的等价解答、学习者是否独立作答。一个绿色 completed 或正式样本计数不能替代后三项。

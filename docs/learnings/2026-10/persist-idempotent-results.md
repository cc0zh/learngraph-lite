# 跨进程幂等要保存结果本身

## 是什么

幂等请求不能只记住“上一次的 run_id”。如果 run 记录只存在内存里，应用重启后即使 repository 还保存着 request_id 到 run_id 的映射，新建的 AgentLoop 也查不到旧 run，最终仍会重新调用模型。

## 为什么需要

LearnGraph Lite 的节点学习是用户可重试的 Agent 操作。刷新页面、重启本地服务或重复提交同一个 request_id 时，用户期望看到同一次学习请求的结果，而不是生成一段新讲解。对真实模型路径来说，这也避免了重复消耗 token 和产生不一致的教学内容。

## 怎么用

在业务 repository 中保存幂等键对应的可交付结果：

- request_id -> run_id 用于追踪运行记录。
- request_id -> final_text 用于在 run 记录不可用时直接恢复用户可见结果。
- 新请求才调用 AgentLoop；已存在结果直接返回，不依赖新的内存 run registry。

## 常见陷阱

- “保存 ID”不等于“保存可恢复状态”；ID 指向的对象如果在另一个进程或内存实例里，就无法恢复。
- 幂等结果应保存业务层需要交付的最小内容，不要把整个内部 transcript 当成业务状态。
- 失败重试和显式重新生成是不同语义；本切片只覆盖成功节点学习请求的重复返回。

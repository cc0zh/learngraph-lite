# React P0 验收闭环

React P0 的验收同时覆盖页面状态和服务端状态。fixture E2E 验证目标、图谱、节点流、Agent 工具出题、按钮出题、正式作答、刷新恢复、停止/重试和响应式布局；Python 协议测试验证有界上下文、完整回合、SSE cursor 恢复和 SQLite 恢复。

本轮将聊天请求明确标记为 `mode: teaching`。fixture 先读取 `get_learning_context`，再按用户要求调用 `create_exercise`，工具结果只返回公共题目，不泄露正式答案。按钮出题继续走独立 HTTP 入口，但共享同一生成用例。新增浏览器场景用一个明确标记的模拟失败响应验证错误可见、显式 `retry_of_run_id`、新 request ID 和原始教学输入保持不变；这不是供应商兼容性证据。

fixture 页面、离线评估和协议测试不能替代真实供应商对模型质量、工具调用兼容性、引用语义和内容质量的测试。真实 smoke 仍需独立记录供应商、模型、run ID、usage 和问题。

## 隔离配置，也要隔离配置来源

清空 `os.environ` 不等于“没有配置”：装配函数仍可能从仓库 `.env` 读回开发者的 Key 和模型名，让缺配置测试失效。只验证缺配置分支时 mock loader；验证加载行为时把 `bootstrap.__file__` 定位到临时目录，放入测试专用 `.env`，并 mock gateway 构造。这既验证进程变量优先级，也保证离线测试不依赖开发者配置、更不会误发付费请求。

## 没收到响应，不代表任务没有执行

POST 响应丢失时，前端不知道后端是否已创建任务。此时应保留完整输入与原 request ID，先查状态，再由用户显式重发同一请求；让后端的幂等机制定位准确任务，而不是用文字相同猜测。只有已经确认的失败 run，才用新 request ID 与原 retry_of_run_id 创建新 attempt。刷新恢复也必须只读，不能偷偷补发请求。

同样，禁用 raw HTML 不等于模型 Markdown 不会触发网络：标准 Markdown 图片仍会自动加载第三方 URL。首版没有图片需求时直接禁用 img，浏览器测试拦截外站并断言零请求；不要把“没有执行脚本”误当作“没有外传数据”。

# 为什么删除不只是执行一条 DELETE

在一个有后台任务、缓存和重试的应用里，“从列表消失”不等于内容真的被删除。本例聚焦一个可复用问题：**怎样让确认删除成为稳定事实，而不是暂时的界面状态。** 实施记录见[学习闭环计划](../../exec-plans/active/product-learning-experience.md)。

## 先想清楚谁拥有数据

学习会话拥有聊天与运行记录；节点拥有教材、题目和成绩；主题拥有图谱和这些节点。删除会话不能顺便清除其他会话仍使用的题目，删除整个主题又不能遗留隐藏的聊天正文。原始上传资料独立存在，删除主题只移除绑定。

后台教材和解释使用独立 session，因此还需要显式的父会话关系。随机 UUID 只表示身份，不表示归属。旧数据缺少关系时不能通过标题、时间或“看起来相近”猜测删除对象。

## 两种不同的迟到结果

```text
后台线程尚未退出 → 删除会话？ → 应拒绝，不能把公开 cancelled 当线程结束
后台线程已经退出 → 删除成功 → HTTP 回执/缓存投影才到达 → 应阻止重新写回
```

第一种需要检查实际工作线程，并把删除与新任务准入放在一致的锁边界。数据库跨表清理在同一短事务完成；提交失败不能先把内存记录清空。

第二种不能只依赖工作线程锁。浏览器迟到回执要在保存命令前检查本页删除状态；SDK 后续保存回答缓存时，也要在数据库事务内拒绝引用已删除 run 的旧投影。只保留身份 ID 的删除标记可以阻止复活，不需要保留被删正文。

校验还必须覆盖真实写入口：只在 HTTP 校验父子作用域，直接调用 SDK 就可能把另一个主题的独立会话错当子会话，随后造成误删。这里在持久化准入事务复核关系，不从 loop 锁内反向获取目录锁，避免死锁。

## “没收到响应”不能当作“没有执行”

DELETE 已提交但响应丢失时，浏览器应保留原目标身份，先 GET：404 确认清理；仍存在则读取当前版本，重新确认后再删除；查询失败只能说未知。刷新不能自动再删。

删除收据还要保存必要的归属 ID。否则刷新后服务器目录已经清空，浏览器反而无法找到原会话对应的草稿和重试命令。它是待核对的操作身份，不是备份或回收站。

## 自检

1. 为什么“停止回答”后可能仍然不能删除？公开状态和实际线程各表示什么？
2. 会话删除保留教材，但教材生成的运行历史要删除，这两者如何区分？
3. 为什么相同 ID 的 DELETE 可以安全重复，浏览器仍不应在刷新时自动重发？

这些机制证明的是作用域与恢复契约，不证明教学效果，也不把基本删除功能包装成高级 Agent 能力。

# Agent 执行、取消与恢复

一次对话可以包含多次模型推理和工具调用。执行层负责让这些步骤受预算、状态与恢复规则约束，但不会替用户确认目标、发布图谱或判分。

## 本页解决什么问题

- AgentLoop 和 AgentRunner 分别负责什么？
- 页面刷新或连接断开，是否会重新调用模型？
- 结果不确定、明确失败与用户取消，下一步有什么不同？

## 用一个例子开始

你在“检索”节点要求生成练习。请求提交后，页面可通过 GET 或 SSE 流式事件查看 run 状态。即使页面断线，题目也可能已经保存；先查询比直接再发一次“生成练习”更安全。

## 正常流程

```text
提交请求 → 校验作用域与请求身份
                       ↓ 保存 run 并排队
              装配上下文与允许的工具
                       ↓
              模型推理 ⇄ 执行工具
                       ↓ 完成或终止
              保存状态 → GET / SSE 读取
```

- **AgentLoop 管任务生命周期：**准入、会话串行、运行状态、取消、持久化与恢复。
- **AgentRunner 管通用回合：**把模型工具调用与结果配对，在预算内继续推理；不认识学习领域的数据和评分规则。
- **应用用例管业务写入：**工具仍须调用相同用例，经过作用域、版本和提交前校验。正式确认、交卷和 ACK 等确定性动作不需要模型循环。

没有后续工具调用时可正常完成；问题卡或目标审核卡的工具也可结束当前回合，等待用户下次输入。失败、取消和预算耗尽是不同终态，不能一律显示为成功。

## 谁决定，保存什么

客户端提交前保存请求身份，服务端保存 run 与公开结果；生成用例还保存题目、学习包等业务产物。run 终止不代表业务产物一定没有提交。

| 已知情况 | 应做什么 | 不应做什么 |
| --- | --- | --- |
| 提交响应丢失，不知道是否执行 | 先只读查询；需要恢复时显式重发原请求身份和完整输入 | 换新身份当成一次新生成 |
| 明确失败、取消、预算耗尽或中断 | 显式 retry，新请求关联原失败 run，并保留逻辑任务身份 | 自动循环重试或把它当作原请求响应丢失 |
| 页面刷新或 SSE 断线 | 读取当前快照与业务结果 | 自动重做写入或重放整段模型调用 |
| 进程重启时有未完成 run | 标为 interrupted，用户决定是否重试 | 启动后自动续跑并产生费用 |

重试能按稳定业务操作键复用已经保存的产物，但不是“所有操作自动回滚”。具体请求、run 与逻辑任务身份见[会话、任务与请求身份](../developer/concepts.md#会话、任务与请求身份)。

## 遇到问题先看这里

- **取消后暂时不能再发任务：**取消是协作式的，阻塞模型调用实际退出前仍占运行名额，不提供硬中断保证。
- **SSE 重连没有补回每个 token：**新连接从最新快照恢复，不提供跨连接完整历史 token 重放。
- **重试按钮无法构造旧任务：**当前前端依赖本浏览器保存的原始命令，不保证跨浏览器恢复任意输入。
- **想靠预算限制所有消耗：**已有调用等预算不等于实际累计 token 硬预算，也不等于每个阻塞调用都能被硬超时切断。

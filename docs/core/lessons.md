# 学习包与交互解释

学习包把教材、步骤、比较和正式题卡放在“学习内容”中，支持围绕具体内容追问。阅读事件、解释任务和正式交卷是三种不同操作，不能互相当作成绩证据。

## 本页解决什么问题

- 为什么长教材不直接塞进聊天气泡？
- 点“读完”或切换步骤，会改变什么？
- 针对内容的解释如何找到正确来源，失败后怎样重试？

## 用一个例子开始

在“检索”节点生成学习包，阅读教材、切换操作步骤，并针对某个步骤请求解释。解释显示在对应内容旁，不混入主教学对话。遇到题卡时，提交正式答案才产生判分与反馈，阅读进度不等于掌握程度。

## 正常流程

```text
生成学习包 → 校验并保存固定组件
                       ↓
              阅读 / 切步骤 / 选择追问
                       ↓ 保存交互事件 ACK
              请求解释 → 独立解释任务

正式题卡 → 提交答案 → 程序判分与反馈
```

ACK 表示程序已经保存该次组件交互。请求解释必须先保存事件，再由服务端结合学习包、组件和事件构造输入，不接受浏览器随意传入一段“来源正文”来冒充已保存内容。

## 谁决定，保存什么

| 内容或动作 | 结果与边界 |
| --- | --- |
| 生成学习包 | 保存新包，不覆盖旧包；只支持 Markdown、单选题卡、步骤与比较表等固定组件，不执行任意 HTML |
| 阅读与步骤事件 | 保存交互 ACK，不调用模型、不更新掌握度 |
| 请求解释 | 在已保存事件上建立独立任务，解释输入来自服务端事实 |
| 提交题卡答案 | 走正式题目作答规则，与阅读 ACK 分开 |

相同事件和解释位置会复用已有任务；仅换一个请求 ID 不表示重新解释。失败、取消或中断后需要显式重试。事件、包版本与解释位置的精确身份规则见[学习包与解释任务](../developer/concepts.md#学习包、ack-与解释任务)。

## 遇到问题先看这里

- **读完后掌握度没变化：**这是正确行为；掌握度只来自有效正式作答。
- **旧学习包能读但不能交互：**图谱内容版本变化或旧组件契约会使它只读，历史反馈仍保留。
- **解释失败后再次点击没有新结果：**先查询任务状态，再使用显式重试，不通过换请求 ID 绕过去重。
- **刷新后仍有已保存内容：**包、事件与聊天分别持久化；刷新只读取，不自动重新生成。

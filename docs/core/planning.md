# 目标规划与图谱审核

Agent 帮你把学习意图变成可审核的知识图谱，但不会替你确认目标或发布图谱。这里先解释使用过程；精确的状态和版本含义见[领域概念](../developer/concepts.md#目标、图谱与版本不是同一个东西)。

## 本页解决什么问题

- 目标确认和图谱发布为什么是两次决定？
- 怎样从一句学习意图走到节点学习？
- 已经发布的图谱为什么要通过提案调整？

## 用一个例子开始

你想“学习 RAG 的检索部分”。在工作台点击“创建目标”并发送意图后，Agent 可澄清范围与基础，再提出目标草稿。你确认后，它生成 `文档切块 → 检索` 等知识节点和前置关系。箭头表示学习前置，不是目录层级或日程安排。

## 正常流程

```text
输入意图 → 澄清 / 提出目标草稿
                    ↓ 用户确认目标
           生成或修订图谱草稿
                    ↓ 用户审核发布
           选择节点 → 开始独立学习
```

1. **审核目标。** 确认范围是否符合你的意图；需要调整时先反馈，不把聊天中的“好”当成已经完成系统确认。
2. **审核图谱。** 查看节点、前置关系和来源，继续反馈或通过图谱管理编辑草稿。模型生成成功只表示草稿已保存。
3. **明确发布。** 发布后再选择节点并点击“开始学习此节点”；仅浏览节点不会建立学习对话。

## 谁决定，保存什么

| 动作 | 决定者与保存结果 |
| --- | --- |
| 提出目标、生成图谱 | Agent 提出，程序校验并保存未确认目标或图谱草稿 |
| 确认目标、发布图谱 | 用户明确操作，程序按当前版本校验并写入 |
| 调整已发布图谱 | Agent 可提出待审核变更；用户接受或拒绝，程序执行版本与图规则校验 |

已发布图谱不能被一次重新生成覆盖。提案可增加或更新节点、增加或移除前置关系；当前不支持删除已有学习节点。内容或依赖变化会更新内容版本，旧题目、作答和学习包保留，但不再作为当前版本的学习证据；优先级等元数据调整不等同于内容失效。

## 遇到问题先看这里

- **生成前仍要求确认：**检查目标审核卡；模型口头确认不能替代用户操作。
- **旧草稿或旧提案冲突：**读取最新状态，重新审核，不强行覆盖新版本。
- **发布响应丢失：**先查询是否已发布，不因刷新重复发布。初次发布和学习初始化仍是两次写入，不是完整原子事务。

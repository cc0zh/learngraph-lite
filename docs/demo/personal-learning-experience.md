# 一次真实学习体验：概率与统计

本页准备一次真实的个人学习体验：保持知识地图与节点学习的产品方向，本轮主题为条件概率、分布与统计直觉。不新增教学模式、不要求通过考试，也不以此把产品限定为统计课程。

**状态：助手按普通用户路径的单次走查已完成，教学语义仍有未通过项；本人真实学习反馈未收集。** 结果见[走查记录](personal-learning-experience-review.md)。初始主题为工具调用与 Agent 运行机制，用户后续选择改学概率与统计；旧目标、资料和调用记录保留，不算作本主题的学习结果。当前产品验证状态仍以[质量与验收](../QUALITY_SCORE.md)为准。本页不是该状态的替代来源。

## 先准备什么

- 学习资料：[概率与统计短笔记](materials/probability-statistics-notes.md)，基于可公开阅读的 OpenStax 教材整理。只将这份非敏感 Markdown 用于本主题，不绑定旧主题笔记，不上传私人资料或本页的观察表。
- 运行空间：使用全新独立 SQLite 与不冲突的本地端口；不复用日常数据或另一会话的服务。同一数据库只运行一个 API 进程。
- 模型授权：准备文件不调用模型。real 模式会把本次问题、相关资料片段与上下文发送给配置供应商，可能产生费用；确认供应商、模型与调用范围后才启动。
- 调用边界：已授权使用 `scripts/real_browser_app.py` 的整轮 14 次供应商请求限额，不修改业务运行内核。更换主题沿用同一个服务的剩余额度，不重启或重置计数。次数限制不等于金额或累计 token 硬预算；达到上限后停止，不自动续额或反复试到成功。

不需要先背笔记。它既是可读资料，也是用来观察资料如何进入学习过程的输入。本人理解程度、问题选择和主观反馈不能由助手代填。

## 从一个自然学习意图开始

在“创建目标”中按自己的说法表达，例如：

> 我想建立概率与统计的知识图谱，重点理解条件概率、常见分布与统计直觉。

这只是表达示例，不是固定测试输入。不要指定工具名、节点数量或执行顺序；不要要求模型自动确认或发布。若 Agent 提问，只回答你实际知道的内容，不方便回答可以跳过，不要求填写时间或产出承诺。

目标出现后，将短笔记显式绑定到该目标；再根据对话审核、确认目标和图谱。记录是否能看懂这些节点之间的关系，不因为模型画出了图就默认结构有用。

## 体验路线：按需要走，不巡展全部功能

| 环节 | 自然操作 | 主要观察 |
| --- | --- | --- |
| 看整体 | 审核图谱，选择自己最困惑的一个节点 | 图谱是否帮助理解主题边界和联系，而不只是增加确认步骤？ |
| 进入节点 | 从该节点开始学习，提一个真实问题 | 能否知道当前在学什么，节点范围是否有帮助？ |
| 使用资料 | 将短笔记显式绑定到当前节点，再结合资料追问 | 能否分清上传与生效，引用原文是否帮助理解？目标绑定不自动替代节点绑定。 |
| 留下学习内容 | 确实需要时，请助手整理当前节点的简短学习材料，在学习内容中阅读与追问 | 内容是否比一串聊天更容易阅读和再次找到？不强制生成全部组件。 |
| 可选练习 | 想检查理解时，请助手出一道练习并本人作答 | 反馈是否有帮助？不要求答对，不把一个样本当作掌握证明。 |
| 再次回来 | 保存当前位置，离开后重新打开并继续已有对话 | 能否找到图谱、节点、教材和记录？刷新本身不应重新生成。 |
| 可选重开 | 调用额度允许且本人需要时，在同节点另开对话，查看已有节点内容 | 能否感受到学习积累仍在，同时理解聊天历史并未合并？开始新学习对话会调用模型。 |

资料问答可以自然追问：“结合我上传的资料，为什么 P(A|B) 和 P(B|A) 不能直接互换？”不需要在问题里告诉模型调用哪个工具。工具选择、引用支持与讲解是否正确需要分别观察，不能只看“已完成”。

看到不理解的节点就记录，不要求按预设路径全走完。体验阻塞先保留事实，不现场扩成功能开发或 Bug 清单；技术阻塞可单独交给负责实现的会话。

## 体验后本人回答的四个问题

1. 哪一次是图谱或节点结构确实帮了我？如果没有，直接写没有。
2. 教材、资料和练习集中在节点后，有没有比单独聊天方便？哪一步反而麻烦？
3. 再次回来时，我能否找到上次的内容并知道怎样继续？
4. 现在我对条件概率、分布或统计直觉更清楚了什么，还有什么不清楚？这是学习者自述，不自动计作已验证能力。

## 观察记录：保留实际，不提前写成功结论

| 观察点 | 实际发生了什么 | 本人感受 | 暂定判断 |
| --- | --- | --- | --- |
| 首次看懂产品与图谱 | 已走过澄清、摘要、16 节点图谱审核与节点选择 | 未收集 | 助手观察：主线成立，首轮步骤与配置感较重 |
| 节点范围与资料使用 | 显式绑定目标与节点，学习包可定位原文；自然追问仍有推导前提遗漏 | 未收集 | 助手观察：资料范围可控，不能由引用推出内容正确 |
| 内容积累与再次继续 | 从首页 3 次点击找回原会话，教材、已读、题目与反馈保留 | 未收集 | 助手观察：本轮返回可用，暂不优先重做入口 |
| 与直接聊天相比的收益或负担 | 未做同条件对照；观察到节点内容组织与前置配置成本 | 未收集 | 只有产品结构判断，学习效果未评估 |

事实可引用本轮 goal/node/run/资料标识及脱敏截图；模型原文、SQLite、trace 和详细 usage 留在忽略的本地证据目录，不直接提交。公开记录只保留本人同意的脱敏摘要，不写求职个人背景或账户信息。

本轮首先完成一个完整案例，不强行形成统计指标。若另做普通聊天对照，应使用相同资料、供应商与模型并说明顺序偏差；额外真实调用先另行授权，不能据一次自用声称准确率、学习效率或普遍效果提升。

## 体验之后才决定改什么

- 已有功能自然发挥作用：保留，不为了项目显得复杂而改动。
- 能力已有但用户难以发现或串联：优先考虑入口、组织与继续体验的收敛。
- 同一真实需求确实无法完成：再提出最小产品补齐方案，由用户确认范围。

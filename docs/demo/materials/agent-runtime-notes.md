# 工具调用与 Agent 运行机制：LearnGraph Lite 学习笔记

这是一份基于本仓库实现整理的学习资料，不是执行指令、测试答案或产品验收报告。只讨论工具调用和运行机制，不包含密钥、私人对话或日常数据库内容。资料整理于 2026-10-17；当前行为以源码和[核心机制说明](../../core/agent-loop.md)为准。

## 工具调用：模型提出请求，程序执行动作

语言模型可以返回一段回答，也可以返回工具调用请求。工具调用请求包含调用 ID、工具名称和参数；它本身不是工具已经执行的证据。

宿主程序根据本轮允许的工具找到处理器，解析并校验参数，执行处理器，再把结果交回模型。模型随后可以继续请求工具，也可以组织最终回答。没有使用工具的回合也可能是正常回答，不要求每条消息都调用工具。

## 回合中的消息如何配对

本项目用 `TextMessage` 表达 user、assistant 和 tool 消息。assistant 消息保存模型提出的 `tool_calls`；对应 tool 消息用 `tool_call_id` 指向原调用 ID。一次 assistant 回复可以包含多个调用，每个结果都要与自己的调用对应。

工具结果通常是结构化数据，而不是模型自己的猜测。未知工具、无效 JSON 或校验错误会作为工具结果反馈给模型，让模型有机会修正；修正仍受执行预算约束，不是无限重试。

## AgentLoop 与 AgentRunner 各负责什么

`AgentLoop` 管理外层任务：校验请求身份与业务范围、准入、排队、运行状态、结果和事件保存，以及取消与显式重试。同一会话的活动任务不能同时执行。

`AgentRunner` 执行内部的模型—工具循环：请求模型、识别调用、执行允许的工具、回传结果并继续。它不认识知识节点、题目或掌握度。应用层负责将学习业务上下文、允许的工具与通用 Runner 组合起来。

并不是每条业务操作都进入模型循环。用户确认目标、发布图谱和正式交卷属于确定性业务操作；部分生成按钮使用直接生成用例。按钮和 Agent 工具可以复用同一业务用例，不能据此称所有操作都是模型自主决策。

## 一次节点学习请求经过什么

以用户在已发布图谱的一个节点中提问为例：

```text
用户发送问题
  → 服务端校验会话、节点和请求身份，保存并准入任务
  → 应用层装配当前节点、允许的业务工具及有限会话历史
  → Runner 请求模型
  → 如果模型请求工具：程序校验、执行并回传结果，再继续模型回合
  → 结果完成后保存运行状态和公共产物
  → 页面通过 HTTP / SSE 读取回答、工具活动与学习产物
```

模型是否需要检索资料、读取学习状态或生成内容，取决于当前问题和可用工具。图中是执行职责，不是要求模型遵守某个固定调用顺序。

## 工具为什么不能拥有无限权限

本项目每次运行只注册该模式允许的工具，学习工具的目标和节点由宿主绑定，不让模型在参数中任意切换。工具参数使用严格 schema 校验。教学模式可以生成练习、学习包和待审核的图谱提案；规划 Agent 没有确认目标或发布图谱的工具。

因此，模型说“已经修改”不等于业务状态真的改变。需要检查处理器保存的结果。模型生成的草稿和提案也不等于用户已经同意。

## 运行状态、学习积累与会话历史不同

一次 run 保存本次任务的状态、结果和事件；一个会话可以有多次 run。节点教材、题目和成绩是业务积累，可以在同一节点的不同会话中查看，但不同会话的聊天历史不会自动合并。

刷新页面是读取已有结果，不应自动再次调用模型。响应丢失时先查询，必要时显式恢复同一请求；已明确失败的任务通过关联原任务的新 attempt 重试。进程重启后未完成任务标为 interrupted，不自动从中间继续执行。

共享预算约束模型调用、工具调用、步骤和估算输入等消耗。取消与 deadline 是协作式的，不能保证立即打断阻塞调用；调用计数和 usage 汇总也不是货币或实际累计 token 的硬上限。

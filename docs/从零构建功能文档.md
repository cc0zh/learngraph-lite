# LearnGraph Lite：从零构建与 Agent 交接文档

> **定位：Agent 应用开发方向的简历作品，不是企业级安全平台。**
>
> 本文是新项目的实施规格，不是对原仓库完成情况的背书，也不是在原仓库上逐项删功能的迁移方案。新 Agent 应从空目录构建，仅把原仓库当作产品与局部实现的参考。
>
> **已确认方向：参考 [HKUDS/nanobot](https://github.com/HKUDS/nanobot) 的 AgentLoop / AgentRunner 职责拆分，自研轻量 Agent 子系统；其余通用能力优先复用高质量开源代码。**
>
> **架构约束：采用轻量分层的模块化单体。学习领域与 Agent 内核互不依赖，由应用层组合；内核可脱离 LearnGraph、FastAPI、SQLite 独立运行。**
>
> **术语：AgentLoop 与 AgentRunner 都属于 Agent 子系统，分别承担外层运行编排与内部模型—工具循环。“双核心”指学习领域与通用 Agent 内核，不是 Loop 与 Runner；只有通用内核要求脱离业务独立运行。**

## 1. 项目定义

### 1.1 一句话介绍

**一个把学习目标变成可审核知识路线，并用具备工具调用能力的学习 Agent 完成“资料学习—交互练习—反馈—下一步行动”的 Web 应用。**

不是通用聊天套壳，也不是万能个人助理。知识图谱用于组织学习依赖，资料引用用于核查回答，练习结果用于解释推荐。

### 1.2 要证明的开发能力

1. 能把 LLM 接进真实业务，而不只拼接聊天 UI。
2. 能实现轻量、可测试的 Agent 循环：上下文组装、工具调用、结果回注、预算、取消、错误处理。
3. 能用结构化输出与服务端校验，把模型建议变成可确认的业务操作。
4. 能完成文档解析、检索、引用定位，并诚实表达检索局限。
5. 能让 Agent 生成声明式交互内容，实现“用户操作 → 业务反馈 → Agent 后续解释”。
6. 能用自动化测试、评估数据集与完整演示证明效果，并交代开源复用和个人贡献。

### 1.3 目标用户与运行方式

- 单个学习者，本地浏览器使用；面试官通过录屏或在本机启动体验。
- 首版只运行在 `127.0.0.1`，不建设公开在线服务。
- 原生 Node.js + Python 启动，无 Docker 前置条件。
- 模型使用服务端配置的 OpenAI-compatible API；首版打通一个真实供应商即可。
- 未配置 API Key 时允许明确标记的 fixture 演示模式；**不得把固定演示数据伪装成模型生成**。

### 1.4 推荐演示场景

“有 Python 基础，希望在四周内理解并做出 RAG 应用。”

上传一份自制或可公开使用的 RAG 资料，生成含检索、分块、引用、评估等节点的路线；选择节点问答，点击引用定位原文；生成分块策略对比卡，完成练习，获得依据前置依赖和错误点生成的下一步建议。准备一个与资料无关的问题，展示系统不会捏造引用。

## 2. 固定边界：保留什么、删除什么

| 类别 | 决策 | 新项目处理 |
| --- | --- | --- |
| 登录与用户体系 | 删除 | 不做注册、密码、JWT、管理员、权限角色、用户切换 |
| 多租户治理 | 删除 | 不做 Workspace/Membership/RBAC/ACL/团队配额/计费 |
| Android | 删除 | 仅 Web，不做 Kotlin、GeckoView、原生桥、二维码连接 |
| 语音 | 删除 | 不做录音、ASR、TTS、WebRTC、实时通话 |
| Docker 与执行平台 | 删除 | 无容器、sandboxd、热池、egress-proxy、宿主桥、运维升级体系 |
| 任意代码执行 | 删除 | Agent 无 Shell、Python eval、任意文件读写、安装依赖、浏览器自动化权限 |
| 长期记忆 | 删除 | 不做画像、跨会话记忆提取/召回、记忆事件流、投影、衰减、治理与记忆向量库 |
| 业务持久化 | 保留 | 保存目标、图谱、文档、会话、练习、成绩、学习进度和运行摘要 |
| 当前会话上下文 | 保留 | 读取当前 session 的有限历史；不自动检索其他会话 |
| 学习进度与推荐 | 保留 | 服务端从显式作答和依赖关系计算，不是长期记忆系统 |
| 文档检索 | 保留 | 检索用户显式绑定的资料，不是检索个人记忆 |
| 交互学习页 | 保留并重设计 | Markdown + 版本化 JSON + 固定 React 组件，禁止生成代码执行 |
| 企业安全平台 | 删除 | 不建设通用策略引擎、审批网络、密码库、多租户审计或合规管理 |

**无登录不等于无数据；无长期记忆不等于无当前会话历史。** 新 session 可以使用用户明确选择的同一目标/节点/资料，以及服务端业务进度，但不能自动读取旧对话、归纳隐式偏好或建立个人画像。

仍需最低工程卫生：API Key 只在后端 `.env`，不进入前端、日志与版本库；请求参数校验；文件大小限制；Markdown 禁止原始 HTML；跨目标资源校验；错误与取消可见。这些不是企业级安全建设。

本地服务仍设置 Host 白名单（`127.0.0.1`、`localhost`），CORS 只允许实际配置的本地前端 Origin；浏览器写请求校验 Origin，拒绝未知或缺失来源，测试/CLI 显式提供可信本地 Origin。回环绑定不能独自阻止恶意网页调用或 DNS rebinding；不采用 `allow_origins=["*"]`。这些是少量请求边界校验，不需要登录或权限平台。

无认证后端包含模型计费与个人资料，**不能直接监听公网或通过隧道暴露**。若以后需要在线 Demo，须另立需求：仅公开静态演示，或引入入口访问限制和费用边界；不偷偷把登录重新做回来。

## 3. 优先级与最终交付

### P0：先形成真实闭环

- 无登录首页与模型可用状态。
- 目标输入、少量澄清、目标确认。
- 小型候选知识图谱、编辑、显式发布、节点选择。
- 自研 Agent 内核与节点学习对话、流式文本、工具调用状态、停止。
- 单选题生成、服务端判分、反馈、学习进度、下一步建议。
- SQLite 持久化，刷新后恢复已完成业务结果。
- fixture 模型、单元测试和至少一条 P0 闭环 E2E（不含尚未建设的资料与学习页，见第 13、14 节）。

### P1：达到本次交接的作品完成标准

- TXT/Markdown/文本型 PDF 上传、解析、中文检索、来源引用与定位。
- 资料可以绑定目标/节点；问答、出题和学习页真实使用检索结果。
- 声明式交互学习页：章节 Markdown、选择题卡、步骤演示卡、对比表。
- 用户操作回流为结构化 Agent 输入，不重复提交、不伪造评分。
- 图谱提案的人工确认、版本冲突提示。
- 失败重试、运行摘要、评估集、真实模型 smoke test、可复现演示材料。

P0 是中间验收点，**不是整项任务完成**；本次交付标准是 P0 + P1。

### P2：首版不做，不能拿来替代 P0/P1

- 联网搜索（只接一个成熟服务，非自建搜索引擎）、向量/混合检索、重排。
- 简答题的模型辅助评分、多模型切换、MCP 的受限只读工具演示。
- 复杂日历排期、自动复习提醒、更多教学组件、效果对照实验。
- 不把已明确删除的登录、移动端、语音、Docker、长期记忆归为“以后自然补上”。

## 4. 用户流程与页面

### 4.1 最小页面集合

1. **目标列表 `/`**：创建/继续目标、资料入口、模型状态；不做复杂仪表盘。
2. **目标规划 `/goals/:goalId/plan`**：输入、澄清、草稿编辑、候选图谱审核。
3. **学习工作台 `/goals/:goalId/learn`**：左侧路线图，中间节点内容/学习页，右侧 Agent；窄屏通过标签切换，不强行挤三栏。
4. **资料页 `/documents/:documentId`**：原文分块、PDF 页码、引用定位、绑定关系；分块原文查看器即可，不必首版实现原版 PDF 高亮。
5. **练习结果**：工作台内反馈与最近作答列表，不必单独建设考试平台。

所有页面必须有 loading/empty/error 状态；长任务展示阶段、耗时、取消和是否可重试。图谱除画布外提供列表入口，节点和按钮可键盘操作。

### 4.2 标准旅程

```text
描述目标 → 回答澄清 → 确认目标
  → 生成候选图谱 → 编辑 → 发布
  → 选择节点 → 绑定资料 → 与 Agent 学习
  → 生成学习页/练习 → 用户操作/作答 → 服务端反馈
  → 更新学习进度 → 显示下一步及理由 → 用户继续
```

### 4.3 必须遵守的交互规则

- AI 生成内容先是草稿，生成不等于用户同意。
- 没有图谱时不能创建脱离节点的“已掌握”结果；可先聊天，但提示未绑定学习路线。
- 练习提交后停留在反馈，不自动跳过错误点；可解释、再学、重新出题。
- 阅读完成、点开节点和学习时长都不能直接提升掌握度。
- 刷新不重新调用模型，不自动提交答案；读取已持久化状态。
- 超时不显示“后台一定失败”，先查 run 状态；重试由用户发起。
- fixture 内容与真实模型结果在界面和导出中可区分。

## 5. 目标、图谱与学习状态的业务规则

### 5.1 目标澄清

目标字段：`title`、`desired_outcome`、`current_level`、`time_budget_minutes`、`constraints`、`document_ids`。

- 只有真正影响路线的信息缺失时才提问，最多两轮、每轮最多三个问题。
- 用户可跳过；未回答的信息以 `assumptions` 显示，不无限追问。
- 结构化草稿由用户修改和确认。Agent 只能生成建议，不能替用户完成确认。
- 用户确认后才允许生成路线；确认只是普通业务状态，不引入审批引擎。

### 5.2 知识图谱

- 使用“目标下的小型学习依赖图”，不是本体知识库或全站实体融合。
- 默认一次生成 8～15 个节点，硬上限 30；每节点含标题、解释、学习结果、预计分钟、优先级。
- 边只有 `prerequisite`：`source → target` 表示学 target 之前应掌握 source。
- 服务端校验 ID 唯一、边端点存在、无自环、无环、时间为正；有错误允许一次模型修复，仍失败则展示可读原因，不静默发布。
- 初始图谱为 `draft`；用户可增删改节点和边，校验通过后显式发布。
- 发布后的节点 ID 稳定；图谱 `revision` 递增。修改语义内容增加 `content_revision`，只调整坐标不使教材失效。
- 后续 Agent 只能创建 `GraphProposal`。用户确认时校验 `base_revision`，冲突返回 409，重新读取而非覆盖。
- 最小提案操作集：增节点、改节点、增/删依赖；首版不做自动删掉已学习节点、实体融合、复杂撤销链。
- 有绑定资料时，生成草稿须真正读取资料片段；仅保存 file ID 不能称“基于资料生成”。

### 5.3 练习、证据与掌握度

首版正式评分仅支持单选题，减少模型判分的不确定性。

- `ExercisePublic` 只包含题目、选项、题目 ID、节点与版本；标准答案/解析放在后端私有字段。
- 学习页中用于讲解的示例题可以立即展示解析，但**不计入掌握度**。
- 用户首次提交某题得到 `Attempt`；标准答案比较由后端执行，不相信客户端传来的分数或 `is_correct`。
- 同题重答用于训练和反馈，不重复计入正式掌握统计；新题需要新 `exercise_id`。
- 新题生成成功后保持不可变，防止历史成绩对应的题目改变。
- 题干/选项归一化哈希用于排除同节点当前版本下的完全重复题；换一个 ID 不应把完全相同的题计成不同题。不承诺首版实现语义去重。
- 使用近期最多五道不同题目的有效首次作答；得分为正确数/题数。
- `unknown`：未作答；`learning`：不足三题或正确率低于 80%；`proficient`：至少三道不同题且正确率 ≥ 80%。
- 页面同时展示样本数和正确率；这只是**练习表现估计**，不得包装为客观能力认证。
- 后续新题答错可以使状态下降。首版不采用原项目“星级只增不减”的规则。
- 客观题判分失败不可能由模型“补一个通过”；模型可补充解释，但判分仍确定性。

`Evidence` 可作为轻量业务记录：链接 `attempt_id`、节点、判分结果和时间。它不是独立事件溯源系统，也不采集整段聊天来自动认证掌握。

### 5.4 下一步行动

推荐先用可解释规则，LLM 只负责把理由组织得易懂：

1. 选出所有未达 `proficient`、且前置节点已达 `proficient` 的可学节点。
2. 有近期答错的可学节点优先补练；其后按用户设置的优先级、预计时间排序。
3. 给定当前可用分钟，优先推荐能完成的小任务；预算不足时推荐一个节点的短讲解，并说明完整任务所需时间。
4. 没有可学节点时指出阻塞前置节点；全部通过则建议综合实践或结束，不伪造新缺口。
5. 返回 `node_id`、`action_type`、`reason_codes`、`reason_text`、`estimated_minutes`、依据的作答 ID 和图谱 revision。

用户可以跳过推荐直接选节点；系统提醒前置依赖，不强制锁课。固定排序和并列规则应写测试，不为首版建设复杂调度器。

## 6. 自研 Agent 子系统：采用 Loop / Runner 拆分，不复制整套产品

### 6.1 参考来源与限制

本次读取了 nanobot 的 README、架构说明、工具基类/注册表和执行循环相关代码，记录参考快照：

- [工具基类](https://github.com/HKUDS/nanobot/blob/23941355a8932609d7fc7ba2820f162d1ea7bea5/nanobot/agent/tools/base.py) / [注册表](https://github.com/HKUDS/nanobot/blob/23941355a8932609d7fc7ba2820f162d1ea7bea5/nanobot/agent/tools/registry.py)
- [上下文构建](https://github.com/HKUDS/nanobot/blob/23941355a8932609d7fc7ba2820f162d1ea7bea5/nanobot/agent/context.py) / [架构说明](https://github.com/HKUDS/nanobot/blob/23941355a8932609d7fc7ba2820f162d1ea7bea5/docs/architecture.md)

这个快照把外层运行编排 `AgentLoop` 与模型—工具执行循环 `AgentRunner` 分开，二者都位于 `nanobot/agent/`，都属于 Agent 范畴。旧教程可能把二者都放在 `loop.py`，新 Agent 应以锁定源码为准。

**本项目显式采用这一职责拆分，不声称 nanobot 本身遵守本文的全部分层规则。** LearnGraph 的 `AgentLoop` 管理一次完整任务：准入、会话/任务关联、预算装配、调用执行器、结果保存与交付；`AgentRunner` 接受准备好的消息与工具，执行内部循环。一项任务可能包含多次模型请求。

**借鉴 Loop / Runner 拆分、小循环、工具注册、结果回注和上下文边界，不整体移植产品外壳。** nanobot 当前包含记忆、渠道、定时任务、Shell、MCP、子 Agent 等能力，不因为它“轻量”就整体安装并开启。不要承诺“固定多少行就完成”；不要直接移植它复杂的兼容/重试/压缩系统。

### 6.2 自研与复用的边界

**自己实现的核心：**Agent 子系统的外层 AgentLoop、通用 AgentRunner、协议上下文管理、工具调用与预算控制；应用层的学习上下文装配、工具白名单、生成用例与领域提案；领域层的图谱/判分/进度/推荐规则，以及教学 JSON 契约和业务评估集。它们是不同模块，不是一个巨型 Agent service。

**必须优先复用：**模型 SDK、HTTP 客户端、Schema 校验、Web 框架、ORM、PDF 解析、中文分词、图谱画布与布局、Markdown 渲染、UI 原语、测试工具。

自研不等于重写 OpenAI SSE 协议、JSON Schema 验证器、PDF parser 或图布局算法。可以改写/摘取 nanobot 中适合的小段 MIT 代码，但记录来源、保留许可，说明修改点。不能把直接复制的实现描述成全部原创。

### 6.3 最小模块与隔离边界

```text
agent_core/                         # 内核：不含学习业务
  runner.py                         # LLM → tools → LLM
  contracts.py                      # RunSpec/RunResult/ModelTurn/ToolResult
  ports.py                          # ModelGateway、进度事件接收接口
  registry.py                       # 当次注入工具的校验、超时、分派
  context_window.py                 # ContextWindowManager：协议裁剪与计量
  execution.py                      # ExecutionControl：通用预算、取消、deadline
  model_gateway.py                  # BudgetedModelGateway：通用模型调用装饰器
application/
  agent/loop.py                     # AgentLoop：应用层的一次任务编排与生命周期
  learning/context_assembler.py     # LearningContextAssembler：业务资料选择
  learning/tool_catalog.py          # 学习场景白名单，由应用层决定
  tools/                            # 业务工具适配器 → 应用用例
  generation/                       # 图谱/练习/学习页的结构化生成用例
  prompts/                          # 学习系统指令与任务模板，不放在内核
infrastructure/model/
  openai_compatible.py               # 官方 SDK → 内核定义的模型协议
  fixture.py                        # 本地演示用适配器；内核测试另有纯 fake
```

这是按架构职责组织的默认目录，**不是把 AgentLoop 移出 Agent 范畴**。按功能看，`application/agent/loop.py` 与 `agent_core/runner.py` 共同组成 Agent 子系统：

| 角色 | 本项目负责 | 明确不负责 |
| --- | --- | --- |
| `AgentLoop`（外层，应用层职责） | 请求去重、并发准入、运行状态/预算、调用场景装配与执行器、统一结果落库和终态 | 再写一套模型—工具循环；内嵌图谱/判分规则、SDK、SQL 或 SSE 连接管理 |
| `AgentRunner`（内层，通用内核） | 模型调用、工具分派、结果回注、协议窗口与通用执行控制 | 识别目标/节点/练习、查询业务库、管理会话持久化或浏览器 SSE |

也可将两者放在同一个 `agent/` 功能目录下，以 `loop.py` 和 `core/runner.py` 等子模块区分职责；此时须同步第 9.3 节及架构测试中的路径映射。**目录不是层次，依赖边界才是；Runner 不反向依赖 Loop，独立导入内核不触发外层初始化。** 默认目录更方便检查边界，不要求为了命名重新拆成服务。

`agent_core` 不得 import `Goal`、`GraphNode`、`Exercise`、Repository、FastAPI、SQLAlchemy、模型厂商 SDK 或其他应用模块。它只接受通用消息、工具定义/回调、执行选项、模型端口和进度事件接收器。工具名在内核看来只是字符串，不内置学习工具列表。

`domain` 同样不依赖 `agent_core`：领域规则只处理普通数据，不认识模型、工具调用、运行预算或流式事件。完整依赖规则见第 9 节。

不引入通用 DAG 编排、多 Agent 群、插件市场、运行时安装工具、独立消息总线或微服务。内核先作为单仓库中的独立 Python 模块，不要求发布 PyPI 包。

### 6.4 默认运行预算

| 项目 | 默认上限 | 行为 |
| --- | --- | --- |
| 模型调用 | 每 run 最多 6 次 | 主循环、工具内生成、修复与应用层重试共同占次数；不额外无限调用“最后总结” |
| 工具调用 | 每 run 最多 12 次 | 多工具响应按总数计数；首版串行执行 |
| 单模型请求 | 60 秒 | 超时分类展示；任何重试仍受 run 总耗时约束 |
| 整个 run | 120 秒 | 预算耗尽保存明确终态与已有产物，不伪造成功 |
| 普通读/写工具 | 15 秒 | 文件解析使用独立有界任务，不算普通读工具 |
| 生成工具 | 最多 60 秒且不超过 run 剩余时间 | 同时受共享模型调用/token 预算约束，不另起无预算的 Agent |
| 单次回复 | 最多 2,000 output tokens | 可配置；教学包采用更小组件分步生成 |
| 输入上下文 | 每次请求 ≤ 12,000 tokens（实测或保守估计） | 包含工具 Schema；同时给回复预留模型窗口空间，不只限制初始输入 |

Token 预算可先用保守估算，但界面与报告标记 `estimated`；供应商返回 usage 时记录实际值，未返回就是未知。计费只有配置了可信价格表才估算，不写虚假精确成本。

`ExecutionControl` 定义通用预算与取消能力，不包含 session/节点/数据库信息。应用层 `AgentLoop` 为每个 run 创建它，并把同一个 `BudgetedModelGateway` 注入主循环和内部生成用例：

- 模型次数只由 gateway 在每次实际请求前预占，**Runner 和生成用例不再重复扣减**；修复和允许的重试走同一入口，失败请求也占次数。
- 工具次数由 Runner 在分派前扣减；生成工具内部的模型请求计模型次数，不额外伪装成新的工具调用。
- gateway 检查剩余耗时、输入/输出上限、取消并汇总 usage；官方 SDK 隐式重试关闭或显式纳入计数，禁止未计数的裸 SDK 调用。
- 生成用例依赖注入的 `ModelGateway`，不依赖 Runner，不另建独立预算；domain 完全不接触这些控制对象。
- 独立内核测试也使用 `BudgetedModelGateway(FakeModel, control)`；Runner 与 gateway 必须共享同一 control。装配时校验这一约束，不允许主循环传入裸适配器绕过预算。

首版同一 session 只允许一个活动 run；全应用最多两个。没有 session 的澄清/图谱等任务通过 `task_ref` 关联业务对象，也使用同一全局准入和预算机制。**AgentLoop 负责并发准入，表现层映射 HTTP 409/429**，不是通用内核规则。使用内存任务表和信号量即可，不加 Redis/Celery。

### 6.5 AgentRunner 内部循环与 AgentLoop 外层编排

```python
async def run(spec, model, on_progress, control):
    # spec.messages/spec.tools 由调用方提供；model 为已装饰的 ModelGateway
    messages = list(spec.messages)
    registry = ToolRegistry(spec.tools)
    window = ContextWindowManager()
    try:
        while True:
            control.check_cancelled_and_deadline()
            messages = window.fit(messages, registry.schemas(), spec.options)
            turn = await model.collect_turn(messages, registry.schemas(), on_progress)
            # 模型调用次数在 gateway 内扣减，不在这里再扣一次
            # SDK 分片先聚合；finish/完整 ID/name/arguments 确定后才允许调用
            if turn.protocol_error:
                raise ModelProtocolError()
            messages.append(turn.assistant_message)
            if not turn.tool_calls:
                return RunResult.completed(turn.text, messages)
            for call in turn.tool_calls:
                control.check_cancelled_and_deadline()
                control.consume_tool_call_or_raise()
                result = await registry.execute_checked(call, control, on_progress)
                messages.append(tool_message(call.id, result))
    except RunCancelled:
        return RunResult.cancelled()
    except DeadlineOrBudgetExceeded:
        return RunResult.budget_exceeded()
    except (ModelFailure, ModelProtocolError) as error:
        return RunResult.failed(generic_error(error))
```

代码仅说明控制流，不是完整实现。内核返回 `RunResult` 并输出通用进度，不验证文档引用、不保存业务数据、不发送 SSE、不发浏览器终态。它不读取数据库、环境变量、学习 task.mode 或业务配置。

应用层 `AgentLoop` 是外层运行入口：创建或复用 run、执行准入、注入共享 control/gateway；学习对话通过 `LearningContextAssembler` / `LearningToolCatalog` 装配后调用 Runner；目标澄清、图谱生成、按钮出题和按钮生成学习页等明确任务直接调用对应生成用例，**不必为了统一入口再让 Runner 猜一次工具**。

场景装配器和用例负责业务上下文、候选/引用验证与产物保存；Loop 负责组织这些调用，保存协议消息/运行摘要、更新运行状态，并产出**唯一的应用终态**。取消、非预期异常、验证与保存失败也由 Loop 的单一收束点处理；表现层把应用事件编码为 HTTP/SSE。预算/取消异常不能被工具适配器吞掉当成普通 tool error，未分类错误必须记录并返回可读失败，不能让 run 永久 running。

```text
HTTP → 应用层 AgentLoop（统一生命周期与预算）
  ├─ 学习对话 → 上下文/工具装配 → AgentRunner → 业务工具 → 应用用例
  └─ 明确生成任务 → 对应生成用例 → ModelGateway → 校验/保存
```

内部工具调用生成用例时复用父 run，不再次进入 Loop 创建子 run。Loop 只编排已声明的少量任务入口，不建设可配置工作流/DAG 引擎。原先称为 `LearningRunService` 的外层职责统一由 `AgentLoop` 承担，**不同时保留两个重复管理运行生命周期的服务**。应用启动/关闭时的未结束 run 处理也经同一生命周期规则收束；进程已退出时无法补发 SSE，重启后的 `interrupted` 通过状态查询可见。

约束：

- 工具名必须精确命中应用层当次注入的工具集合。未知工具/参数错误返回有结构的 tool error，让模型有机会修正；不能模糊匹配后执行。
- 使用 Pydantic 校验参数、长度与枚举，未知字段拒绝；不要自研 Schema 类型转换器。
- tool_call ID 与结果逐一对应；把完整 assistant tool_calls 和相应 tool messages 成组保存/裁剪，避免孤立结果破坏模型协议。
- 中断时尚未配齐结果的工具消息组可以保存为部分运行记录，但应用层不能把它当完整历史再次传给内核；下一次装配只选择完整协议回合。
- 每次模型调用前重新计量上下文、工具 Schema 和新工具结果，必要时成组裁剪较早历史并截断过长结果。当前必需指令/任务仍超限时返回明确 `context_budget_exceeded`，不直接发送；工具内结构化生成请求同样适用。
- 多工具先串行，写操作不得并发；相同提案/生成请求在重试时返回已创建结果。
- 传回模型的资料标记为“数据而非指令”，不允许文档内容扩展工具权限。
- 不支持 tool calling 的模型明确提示能力缺失；不得通过执行回复里的 JSON/代码块冒充原生工具调用。
- JSON 生成先 Schema 校验，至多一次修复；修复占预算。失败不发布半合法业务数据。
- 临时 429/5xx 在尚未输出内容且未执行写工具时可有限退避重试；显式限制 SDK 隐式重试。已输出内容不整段自动重试，避免重复文本/计费/写入。
- 取消后不得启动下一次工具或模型调用；已完成提交的业务写入保留，界面说明停止不是回滚。

### 6.6 应用层的最小学习工具目录

以下是 **LearnGraph 应用层适配器**，不属于 `agent_core` 内置能力。`ToolSpec` 仅携带 name、description、输入 Schema、回调和超时选项；目标/节点/资料作用域由应用层绑定到适配器，不传给内核自行解释。

| 工具 | 作用 | 数据权限与副作用 |
| --- | --- | --- |
| `get_learning_context` | 查看选定目标、节点、前置与进度 | 只读，作用域由服务端注入 |
| `search_documents` | 在显式绑定资料内检索片段 | 只读，返回 chunk ID、定位与短文本 |
| `read_document_chunk` | 读取指定片段原文 | 只读，校验片段属于本目标可用资料 |
| `create_exercise` | 生成并保存单选题 | 有界写入，后端验证私有答案，对主对话只返回公共题目与 ID |
| `create_lesson` | 创建声明式学习页 | 有界写入，保存为版本化业务产物 |
| `propose_graph_change` | 创建候选路线变更 | 仅提案，不直接发布或修改当前图谱 |
| `get_next_action` | 获取规则推荐及依据 | 只读，不让模型任意指定掌握状态 |

上传、答案提交、图谱确认、取消 run 由用户触发普通 API。**Agent 不注册** `set_mastery`、`submit_user_answer`、`confirm_graph`、`shell`、任意 SQL、任意路径文件读取。

生成工具只接受节点、教学目的、题量等受限参数。应用层的 `GenerateExercise` / `GenerateLesson` 用例通过注入的带预算 `ModelGateway` 请求结构化候选（至多一次修复）；再调用 domain 的纯校验规则，通过 Repository 端口保存。domain 不调模型、数据库或 Runner。私有答案留在用例与持久化内部，不能通过 ToolResult 回注主对话。首版不做题目发布审批：校验通过后保存为不可变正式题目，失败不产生可作答实体。

应用层 `LearningToolCatalog` 按任务暴露小集合，例如资料问答仅开放上下文与文档读工具，节点教学才开放练习/学习页；内核接收已经确定的集合，不再根据业务模式二次选择。普通生成按钮通过 Loop 直接调用对应应用用例，Agent 通过工具适配器调用同一用例，不能各自实现一套生成/校验/保存逻辑；判分与普通业务写入则直接调用用例，不必进入 Loop。首版无需工具搜索市场或“无限渐进披露”。

### 6.7 两种上下文与事件边界

**应用层 `LearningContextAssembler` 决定放什么：**系统规则 → 当前确认目标/节点及前置摘要 → 显式学习表现 → 当前 session 最近完整回合 → 本次选择资料/片段 → 用户本轮输入。它通过 Repository/检索端口取普通 DTO，不能把 ORM 对象或数据库 Session 交给内核。

**内核 `ContextWindowManager` 决定怎么合法发送：**计量普通消息与工具 Schema、保留必要消息、成组裁剪 tool 协议回合、限制文本结果。不识别 Goal、引用版本或学习掌握度。具体学习资料选择和引用校验仍由应用层完成。

- 裁剪旧历史，不做持久化长期摘要或用户画像；当前会话的临时组织是允许的。
- 应用层按需检索资料，初始不塞整本 PDF；应用层的引用检查只允许本轮检索/读取过的来源。
- 显示工具名、参数摘要、耗时、成功/失败、结果摘要，**不展示模型隐藏思维链**。
- 数据库存储的模型协议消息不是浏览器 DTO：消息历史、run snapshot、tool 事件、教学包与运行摘要统一用公共 Schema 输出，过滤私有答案、原始生成 JSON、内部路径和敏感参数。结构化出题服务的流不能转发给学习者；提交后才通过作答反馈 API 返回该题解析。
- 保存 `run_id`、模型/提示词版本、调用次数、token usage（或未知）、时间、工具结果状态、错误类别和生成实体 ID。
- 不建分布式追踪平台；运行摘要页、结构化日志与本地评估报告足够。

内核进度只包含通用 `TextDelta`、`ToolStarted`、`ToolFinished` 等数据。应用层负责安全投影、产物引用、运行关联、分配 seq、内存快照与结果落库；表现层负责事件信封编码、SSE 心跳与连接。内核中没有 `artifact.ready`、引用 C1 或浏览器连接管理。运行终态的唯一写入点是应用层 AgentLoop 的收束点，不在 Runner、场景用例与路由各写一次；公共事件投影可用独立小模块，不让 Loop 内嵌全部业务逻辑。

## 7. 上传资料、检索与引用问答

### 7.1 解析范围

- 首版：UTF-8 TXT、Markdown、文本型 PDF；单文件默认 ≤ 10 MB，PDF ≤ 100 页，抽取文本 ≤ 200,000 字符。
- 使用 pypdf 抽取 PDF 文本，禁止执行附件/脚本；解析任务有超时，必要时在可终止的子进程运行 parser。这不是给 Agent 执行代码的沙箱。
- 扫描 PDF、乱码、加密文件明确 `unsupported`；扫描文件的原因码为 `needs_ocr`，不是额外状态。不宣称首版支持 OCR、Word/PPT、任意网页。
- 文件用服务器生成 ID 命名，原文件名仅展示，不接受用户路径；解析完成后按页/标题切块。
- 原文分块保存 `document_id`、`revision`、`chunk_id`、页码或标题、起止字符、文本哈希。
- 状态：`uploaded → parsing → ready / failed / unsupported`；只有 ready 文件可检索。
- 进程重启把未完成解析同步置为 `failed`、原因 `interrupted`，不能一直显示 parsing。`POST /documents/:id/reparse` 可复用保留的原始文件重试，不必重新上传；已 ready 时默认返回现有结果，失败重试不改变文件内容 revision。

### 7.2 最小检索方案

采用 SQLite FTS5 + 中文分词，不先引入向量数据库。

1. 用成熟 jieba 分词同时处理资料和查询，统一大小写/空白；FTS 搜索字段写入空格分隔的分词，原始文本另存用于展示。
2. 使用参数化 SQL，并转义/构建 FTS 查询表达式；不能把用户输入直接拼成 `MATCH` 语法。
3. 按 BM25 排序返回默认 top 5，限制片段与总文本大小；不假装 BM25 分值就是“可信度”。
4. 检索范围只包含当前目标/节点显式绑定的文件；无绑定时提示选择资料。
5. 启动检查 SQLite 是否支持 FTS5；不支持时给出明确安装说明，不静默切成空结果。

称之为**检索增强问答/最小 RAG**可以；不能写“已实现向量语义召回、重排、GraphRAG”。P2 加 embedding 时必须做效果对照，不因简历需要而堆服务。

### 7.3 引用契约

检索返回结构化来源，例如：

```json
{
  "citation_id": "C1",
  "document_id": "doc_1",
  "document_revision": 1,
  "chunk_id": "chunk_7",
  "locator": {"page": 3, "heading": null},
  "text_hash": "sha256-of-normalized-chunk",
  "excerpt": "用于回答的原文片段"
}
```

- Agent 可在回复中用 `[C1]`；服务端保存本 run 的 citation map，并验证引用只来自实际返回的片段。
- 未知引用不得变成可点击链接；标记未验证，记录评估错误。
- 点击引用打开原文分块，显示文件名/页码/版本；**不承诺自动验证句子语义完全被原文支持**。
- 引用存在性/作用域/版本是程序验证；内容是否真正支持答案由评估样例检查，不能混为一谈。
- `C1` 等短 ID 的作用域是一次回答或一个产物版本，不是全局 ID。图谱草稿、题目、学习页持久化并返回各自的 citation map（不能只存 `[C1]`）；内部多步生成共用来源表，避免同一包里 C1 指向不同片段。
- 删除或重新上传文件使旧版本引用 `stale/unavailable`，历史回答仍可读，但不自动指向新内容。
- 找不到相关资料时明确说明；用户可以选择普通知识解释，但输出标记“非基于上传资料”，不附伪造引用。
- 目标图谱、题目、学习页若声称“基于资料”，其生成上下文必须含真实检索片段，并保存引用。

## 8. Agent 生成的受控交互学习页

### 8.1 产品定义

学习页是一个可版本管理的教学包，不是任意生成网站。Agent 生成内容与组件参数，前端执行已写好的组件逻辑。

首版组件白名单：

1. `markdown`：章节与解释，禁用 raw HTML 和危险 URL。
2. `quiz_choice`：展示服务端已有练习，只引用 `exercise_id`，不内嵌正式答案。
3. `stepper`：步骤标题、说明、固定槽位值，前进/后退/重置；不接受代码、公式执行器或任意事件处理函数。
4. `comparison_table`：有限行列的文本对比，不执行表达式。

示意结构：

```json
{
  "schema_version": 1,
  "node_id": "node_chunking",
  "node_content_revision": 1,
  "title": "理解文档分块",
  "blocks": [
    {"id": "b1", "type": "markdown", "text": "## 分块的目的\n先阅读资料 [C1]。"},
    {"id": "b2", "type": "stepper", "steps": [
      {"title": "原文", "description": "观察连续文本", "slots": {"text": "示例段落"}},
      {"title": "分块", "description": "保留适量上下文", "slots": {"text": "分块 A / 分块 B"}}
    ]},
    {"id": "b3", "type": "quiz_choice", "exercise_id": "exercise_1"}
  ],
  "citation_ids": ["C1"]
}
```

完整 Schema 由后端 Pydantic 定义、前端 Zod 对齐；限制 blocks ≤ 20、steps ≤ 12、表格 ≤ 20 行/6 列、文本长度。组件 ID 必须唯一，题目必须属于同一节点，且其 `content_revision` 与教学包一致。旧包只引用对应版本的旧题，查看时显示历史状态。

**禁止字段：**HTML、JS、JSX、CSS 代码、动态 import、bundle、事件函数、任意 URL 资源、远程脚本、`eval`。不是给生成 HTML 加一个 iframe 就算完成此要求。

### 8.2 生成与版本

- 状态：`queued → generating → validating → ready / failed / cancelled / interrupted`。
- 分阶段写入有版本的教学包：先章节，再可选互动与题目；只有合法已保存的 block 才可展示。
- 同节点内容 revision 和同配置的生成请求可返回已有包；显式“重新生成”产生新版本。
- 节点语义改变后旧包标记 outdated，可查看，不自动充当当前最新内容；仅布局变化不失效。
- 首版仅按需生成选中节点，不全图自动批量生成，不搬运七阶段调度与租约体系。
- 失败可重新发起，复用已验证内容或从头生成要明确标记；不宣称重启后能恢复模型流或原进程任务。

### 8.3 双向交互

```text
固定组件 → 用户点击/选择 → POST /lessons/:id/events
  → 校验 block/action/lesson version/event_id → 保存业务事件/进度
  → 返回业务 ACK 和反馈
  → 用户选择“让 Agent 解释” → POST /sessions/:id/runs 引用该事件
  → AgentLoop 创建或复用关联的学习 run
```

- 白名单动作：`mark_read`、`step_changed`、`request_explanation`；作答走统一 attempts API。
- 学习事件记录 `event_id`、`lesson_id/version`、`block_id`、`action`、受限 payload；同一 ID 去重。
- 解释请求携带 `source_event_id` 与 `explanation_slot`（首次固定为 `initial`）。服务端校验事件属于当前目标/节点/教学包，并从已保存事件构建解释输入，不采用客户端伪造的事件摘要。`(source_event_id, explanation_slot)` 标识一个逻辑解释任务，事件保存本任务的 `root_task_id` / 首个 `run_id` 关联；重复请求即使换了 `request_id` 也返回已有任务，不重新调用模型。
- 关联写入、初始 run 与用户输入保存使用同一短事务，保证同一业务键只创建一个任务；可在 LessonEvent 的关联字段中用事务条件更新实现，不要求独立事件平台。创建失败不留下假关联；响应丢失或并发重复提交可安全重试。失败后的显式 run 重试沿用 root 与 slot；只有显式“重新解释”才使用新 slot 创建新任务，网络重试不能自行更换 slot。
- 前端不能传 `mastery=100` 或通过“通关”事件写成绩。
- 操作失败不假装已保存；重复点击不重复产生 Agent 回复。
- 普通切换步骤只本地更新/防抖保存，**每一次点击不必都调用模型**，避免成本和聊天噪声。
- Agent 只收到服务端验证后的事件摘要，不把任意组件数据当作系统指令。

## 9. 技术架构与从零目录

### 9.1 默认技术选型

| 层 | 选型 | 原因 |
| --- | --- | --- |
| Web | React + TypeScript + Vite | 原仓库有成熟经验、快速构建本地应用 |
| 路由/数据 | React Router、TanStack Query | 不自研路由、请求缓存和失效机制 |
| UI | Tailwind、shadcn/ui/Radix、Lucide | 基础组件复用，重点开发业务交互 |
| 图谱 | `@xyflow/react` + dagre | 复用画布和有向布局，只写业务节点/审核 |
| 文本 | Streamdown，或成熟 Markdown renderer | 与后端自定义事件适配，禁止 raw HTML；确认流式兼容 |
| API | FastAPI + Pydantic | 结构化接口、输入校验、OpenAPI |
| Agent | 参考 nanobot 自研 AgentLoop + AgentRunner | 同属 Agent 子系统；Loop 外层编排，Runner 为独立通用内核 |
| 模型 | openai-python + 可配置 base URL | 不自研模型 HTTP/SSE 协议；验证实际 tool calling |
| 存储 | SQLite/WAL + SQLAlchemy + Alembic | 单进程单用户，普通迁移即可 |
| 文档 | pypdf、jieba、SQLite FTS5 | 首版低依赖、中文资料可用 |
| 测试 | pytest、Vitest、Testing Library、Playwright | 内核/业务/UI/E2E 各有覆盖 |

初始化时选择互相兼容的稳定版本并提交锁文件。不要复制原仓库全部 dependencies，也不要硬套其当前版本号。Python 3.11+、Node.js 22 LTS 或符合所选 Vite 要求的版本。

```text
React Web
  ├─ 路线图/学习页/资料/练习
  └─ HTTP + SSE
          ↓
表现层（FastAPI 路由 / 请求与响应 / SSE 编码）
          ↓
应用层（AgentLoop / 场景用例 / 学习上下文 / 工具适配）
          ├───────────────┐
          ↓               ↓
领域层                  Agent 内核（AgentRunner）
图谱 / 练习 / 进度      通用模型—工具循环
推荐 / 教学包规则       协议裁剪 / 预算 / 取消
          └──── 端口契约 ───┘
                     ↑ 实现端口，不反向依赖具体实现
基础设施（模型 SDK / SQLite / 文件解析 / FTS / fixture）

bootstrap 装配上述模块；仍为一个后端进程，不是五个服务。
```

没有 Docker，没有认证网关，没有分布式队列，没有长期记忆服务。后端默认单 worker；多 worker 会破坏内存任务表与取消控制，不在首版支持范围。

### 9.2 分层职责：领域与内核是两个独立核心

“双核心”指 `domain` 与 `agent_core`，不是 AgentLoop 与 AgentRunner。Loop 和 Runner 同属 Agent 子系统；Loop 因承担本项目运行编排而位于应用层，只有 Runner 及其通用协作模块属于独立内核。这是本项目的架构选择，不是按文件夹否认它们的功能归属。

| 模块 | 负责 | 明确禁止 |
| --- | --- | --- |
| `presentation` | HTTP 入参/公共响应、错误状态码、SSE 编码、Origin/Host 边界 | 直接查 ORM、判分、拼 Agent prompt 或写循环 |
| `application` | AgentLoop 的运行生命周期与外层编排；场景用例、作用域检查、业务上下文、工具目录/适配器、生成与引用验证 | 内嵌 SDK/SQL/解析实现；重复实现 domain 规则或 Runner 循环；多处写运行终态 |
| `domain` | 图谱校验/提案规则、客观判分、掌握计算、下一步规则、教学包约束 | 调模型、数据库、HTTP；接收 Runner/ExecutionControl/ORM Session |
| `agent_core` | 通用模型/工具循环、工具协议、消息窗口、预算/取消/进度契约 | 理解学习实体；查资料/数据库；处理业务引用或浏览器 SSE |
| `infrastructure` | 实现模型、Repository、文件、parser、检索等端口；ORM 映射 | 决定学习工作流、绕过领域规则自行判分 |
| `bootstrap` | 创建配置/适配器/用例并注入依赖，应用启动/关闭 | 承担业务判断；成为各模块运行时查找依赖的 service locator |

**领域层与内核互不 import，也不互相调用。** 例如 `calculate_progress(attempts)` 不知道 Agent；Runner 不知道 `NodeProgress`。应用层的 `SubmitAttempt` 调前者，`AgentLoop` 组织学习场景并调用后者；业务工具通过适配器调用应用用例，再由用例使用领域规则。

AI 内容生成属于**应用用例**，不是纯领域规则：`GenerateExercise` 调模型获得候选，调用 domain 校验，再经端口保存；`grade_choice` 只处理输入答案和标准答案。能做纯函数就不为它造一个带数据库和模型的 service 类。

### 9.3 代码依赖与装配规则

```text
presentation  → application
application   → domain + agent_core + 自己定义的 I/O 端口
domain        → 自身与少量基础库
agent_core    → 自身与少量基础库
infrastructure → application 的 I/O 端口 + domain/agent_core 契约
bootstrap     → 所有模块（仅用于装配）
```

- 箭头表示允许的 **import 依赖**。运行时通过端口调用具体适配器，不等于应用层 import infrastructure。
- 默认路径中 `application/agent/loop.py → agent_core/runner.py` 是允许的外层到内层依赖，反向禁止。若合放到 `agent/` 功能目录，按子模块职责保留同样规则，不能把整个目录都当通用内核，亦不能在包入口自动导入 Loop。
- `domain`、`agent_core` 不依赖彼此或其他 app 子模块；可使用标准库/Pydantic 等基础库，不引入 Web/ORM/模型供应商 SDK。
- 路由注入已装配的用例/应用 facade；禁止路由通过 `get_db()` 直接实现业务，禁止 HTTP/SSE 类型泄漏到内核或领域规则。
- Repository/检索/parser 端口放在 `application/ports.py`；通用模型与内核进度契约放在 `agent_core/ports.py`。基础设施实现这些端口。
- ORM 表在 `infrastructure/persistence`，与 domain 数据对象分开；应用层拿普通 DTO，不向内层传 SQLAlchemy 对象。API 公共 DTO 再过滤私有字段。
- 依赖通过构造参数或函数参数显式注入。`bootstrap.py` 绑定实现；不在每个函数里临时创建 SDK/数据库、不全局查服务、不使用重量级 DI 框架。
- `app/__init__.py` 不自动 import FastAPI、数据库或装配代码；导入内核不应触发应用启动。
- 按真实替换点定义少量 Protocol，不为每个纯函数/类创建接口，不建设通用 BaseRepository、DDD 聚合框架或事件总线。

### 9.4 最小契约与调用示例

| 契约 | 定义位置 | 内容/实现 |
| --- | --- | --- |
| 应用运行命令/任务关联 DTO | application/dto | kind、session_id 或 task_ref、request_id、retry/source-event 关联等；AgentLoop 的输入，不传给 Runner 自行解释 |
| `RunSpec` / `RunResult` | agent_core/contracts | 普通消息、工具集合、通用选项；文本/协议消息/终止原因，不含学习 DTO |
| `ModelGateway` | agent_core/ports | 通用模型请求、流式内容、tool calls、结构化输出选项与 usage；不含 SDK 对象 |
| `ToolSpec` / `ToolResult` | agent_core/contracts | Schema、回调、超时、结果/通用错误；回调由 application 提供 |
| `ExecutionControl` | agent_core/execution | 模型/工具次数、deadline、取消与通用预算；不含业务 ID/Repository |
| 进度接收契约 | agent_core/ports | 通用文本/工具进度；应用层将其关联 run 并生成安全事件 |
| 少量 Repository 端口 | application/ports | 普通 DTO 的读取/保存、revision/幂等条件；SQLite 实现在 infrastructure |
| 文档检索/解析端口 | application/ports | 已确定作用域的资料检索、chunk 读取、固定文件解析；不负责挑选学习目标 |

`BudgetedModelGateway` 是内核中的通用装饰器，实现同一个模型端口，包裹基础设施 SDK 适配器。AgentLoop 在一次 run 开始时实例化它并注入 Runner/生成器，所以可共享预算而不让业务依赖 Runner。它不持有领域实体、数据库或工具目录。

#### 例 A：Agent 生成练习

```text
HTTP → AgentLoop（创建/复用 run，装配共享预算）
  → LearningContextAssembler 取业务 DTO 并组装消息
  → LearningToolCatalog 注入 create_exercise 等工具
  → AgentRunner 决定调用 create_exercise
  → 应用层工具适配器校验目标/幂等键并调用 GenerateExercise
  → 注入的 ModelGateway 请求候选（同 run 预算；私有流不转发）
  → domain 校验题目 → Repository 端口保存 → 返回公共题目/ID
  → 内核回注通用 ToolResult 并继续对话
  → 场景验证引用/结果 → Loop 保存消息/运行摘要并收束终态
  → 表现层输出公共 DTO/SSE
```

#### 例 B：用户提交答案，不需要 Agent

```text
HTTP → SubmitAttempt → Repository 读取题目/历史作答
  → domain.grade_choice + calculate_progress
  → Repository 在短事务内保存 Attempt/NodeProgress（校验唯一性/版本）
  → 返回公共反馈 DTO
```

#### 例 C：按钮直接生成练习，不需要 Runner 选工具

```text
POST /nodes/:id/exercises → AgentLoop（kind=exercise，统一预算/去重/状态）
  → 同一 GenerateExercise → ModelGateway → domain 校验 → Repository 保存
  → 公共产物事件 → Loop 收束终态
```

例 A/C 共享生成用例，例 B 使用独立的确定性判分用例；三个流程使用一致的领域规则与持久化契约，但按钮生成无需 Runner，判分/推荐无需 Loop、Runner 或模型。事务由应用用例界定，经持久化端口执行；不跨模型 await 持有锁。提交竞争时使用唯一约束/版本检查，不能让旧计算覆盖新进度。

### 9.6 配置与运行约定

模型配置由后端 bootstrap 读取，例如 `MODEL_BASE_URL`、`MODEL_NAME`、`MODEL_API_KEY`、`MODEL_MODE=real|fixture`，再注入适配器；内核/领域不读取 `.env`。不做浏览器保存多 Provider Secret 的管理平台。URL 是开发者可信配置，不是终端用户任意输入的抓取地址。

新 Agent 应提供并实际验证以下命令；**这些不是当前原仓库已经支持的新项目命令**。根 `package.json` 用 npm workspaces 覆盖 frontend，确保根 `npm install` 安装前端依赖：

```bash
npm install
cd backend
uv sync --extra dev
uv run alembic upgrade head
cd ..
npm run dev        # 启动 127.0.0.1:5173 和 127.0.0.1:8000
npm run check     # typecheck + lint + build + 后端检查
npm run test      # 确定性单元/集成测试
npm run test:e2e  # 另行安装 Playwright 浏览器后的本地验收
```

前端 Vite 代理 `/api`，同源调用；首次启动创建忽略的数据目录。README 分开写 Windows PowerShell 和常规终端命令，明确 Node/Python/uv 与浏览器安装前置，不自动下载未知可执行文件。

## 10. 最小数据模型与一致性

不建立 User、Workspace、Membership、MemoryEvent。采用普通关系表与少量结构化 JSON。

下表是**持久化规格**，不是要求把 SQLAlchemy model 当作领域实体。具体表映射在 infrastructure，domain 使用独立普通数据；application 通过端口完成转换与读写。

| 实体 | 关键字段/关系 | 说明 |
| --- | --- | --- |
| `Goal` | id、目标字段、assumptions、status | draft/confirmed/active/archived |
| `Graph` | goal_id、revision、status | 当前学习依赖图 |
| `GraphNode` | graph_id、id、content_revision、label、outcome、estimated_minutes、priority | 节点定义与布局分开处理 |
| `GraphEdge` | graph_id、source、target | prerequisite；唯一约束与无环校验 |
| `GraphProposal` | graph_id、base_revision、operations、status | pending/accepted/rejected/conflicted |
| `Session` | goal_id、node_id、created_at | 一会话服务当前选定学习上下文 |
| `Message` | session_id、role、status、text、parts_json、citation_map | 保存已完成内容与完整 tool 消息组，区分部分输出 |
| `AgentRun` | session_id 或 task_ref、root_task_id、request_id、retry_of_run_id、input_message_id、kind、status、usage、error_code、result_refs | 另含模型/耗时；不需要持久化每个 token 事件 |
| `ToolInvocation` | run_id、call_id、name、status、duration、result_ref | 摘要/脱敏参数，不保存隐藏思维链 |
| `Document` | id、revision、name、hash、storage_path、status | 同内容上传可复用解析结果 |
| `DocumentBinding` | document_id/revision、goal_id、可选 node_id | 显式资料作用域 |
| `DocumentChunk` | document_id/revision、文本、定位、hash、search_text | FTS 索引可重建，不是规范业务事实源 |
| `Exercise` | node_id/content_revision、public_json、private_answer、explanation、citations | 生成后不可变、正式答案私有 |
| `Attempt` | exercise_id、submission_id、answer、score、feedback、created_at | 首答统计/练习重答区分 |
| `NodeProgress` | node_id、状态、sample_count、accuracy、last_attempt_at | 根据有效作答重算 |
| `Lesson` | node_id/content_revision、version、schema_version、manifest、citation_map、status | JSON 教学包 |
| `LessonEvent` | event_id、lesson_id/version、block_id、action、payload、explanation_refs | 普通业务事件；解释 slot 关联 root task/首个 run，不做通用 event store |

`Evidence` 如独立落表只需指向 Attempt；也可以先由 Attempt 查询投影，避免重复保存同一事实。下一步建议可以即时计算，不需要独立大型推荐存储。

一致性要求：

- 数据库外键开启；写入题目、作答与进度采用短事务，不跨模型请求持有事务锁。
- 每次作答使用 `submission_id`；同 ID/同 payload 返回原结果，同 ID/不同 payload 返回 409。
- 所有模型任务由 AgentLoop 使用 `request_id` 去重；同 ID/同 payload 返回原 run，同 ID/不同 payload 返回 409。生成按钮和学习对话使用相同规则；同样的请求不能因双击或网络重试重复调用模型。显式重新生成使用新 ID。
- 初次生成创建稳定 `root_task_id`；显式失败重试提交新 `request_id` 和 `retry_of_run_id`，沿用 root 与 `input_message_id`，不重复保存用户消息。真正“重新生成”不带 retry 关系，创建新 root/产物版本。
- 生成用例使用服务端生成的 `operation_key`，例如 `root_task_id + operation_kind + node_id + content_revision + purpose_slot`，并建立唯一约束。`operation_kind` 是稳定业务操作（如 exercise/lesson/proposal），按钮与工具进入同一用例，不能靠入口名称区分去重。同键同 payload 返回原产物，同键不同 payload 返回 409/结构化冲突；不能用新 run ID、模型轮数或 tool_call ID 当业务去重键。首版每个任务对同节点的每类生成只允许一组题目/一个教学包，题量在批次参数内指定，避免不稳定调用顺序。
- 解释任务额外按第 8.3 节的 `(source_event_id, explanation_slot)` 去重，并原子保存事件与 root task/首个 run 的关联；约束的是逻辑任务唯一，不禁止显式失败重试产生同 root 的新 run。只分别去重 event_id 和 request_id 不足以证明解释任务唯一。
- 首答唯一性用数据库约束/事务保证，不只靠前端禁用按钮。
- 图谱发布/提案确认带 `expected_revision`；旧版本返回冲突。
- 所有资源都校验属于请求的目标/图谱；单用户仍不能把不相关节点/题目混写。
- 图谱节点语义修订后旧成绩保留作历史，但当前掌握统计只使用匹配当前 `content_revision` 的题目；因此进度可重置，用户要看到原因。
- 原始文件与教学包历史保留策略简单明确；首版不提供破坏性级联删除已学习节点。资料删除要使绑定/检索失效，历史引用诚实降级。
- 应用重启将未结束 run/job 标为 `interrupted`，允许用户重新发起；不声称跨进程断点续跑。

## 11. API 与流式事件契约

统一前缀 `/api`，由 FastAPI OpenAPI 输出 Schema。下面是新项目最小合同，可合并相近路由但不能省略语义。

路由只做表现层适配，调用应用用例并把领域/应用错误映射为状态码；它不直接调 SDK、Repository 实现或 Runner。Pydantic 入参/公共响应不替代应用作用域检查与领域规则。

| API | 用途 |
| --- | --- |
| `GET /health`、`GET /model/status` | 本地服务/模型配置状态，不返回 Key |
| `GET/POST /goals`、`GET/PATCH /goals/:id` | 目标列表、创建、编辑 |
| `POST /goals/:id/clarify` | 创建澄清 run，返回 run ID |
| `POST /goals/:id/confirm` | 用户确认结构化目标 |
| `POST /goals/:id/graph-drafts` | 创建图谱生成 run |
| `GET/PATCH /graphs/:id`、`POST /graphs/:id/publish` | 读取/修改草稿、校验后发布 |
| `POST /graph-proposals/:id/decision` | 用户接受/拒绝，检查 base revision |
| `POST /sessions`、`GET /sessions/:id/messages` | 绑定上下文、读取历史 |
| `POST /sessions/:id/runs` | 保存用户输入并创建学习 run；可引用 source_event_id/explanation_slot，解释输入由服务端构建 |
| `GET /runs/:id`、`GET /runs/:id/events`、`POST /runs/:id/cancel` | 运行状态、SSE、停止 |
| `POST /documents`、`GET /documents/:id`、`GET /documents/:id/chunks`、`POST /documents/:id/reparse` | 上传、解析状态、原文、失败后复用文件重试 |
| `POST/DELETE /goals/:id/document-bindings` | 显式绑定/解绑资料 |
| `POST /goals/:id/document-search` | 有界检索，返回引用元数据 |
| `POST /nodes/:id/exercises` | 按钮直接创建练习生成 run，复用 Agent 工具的 GenerateExercise |
| `GET /exercises/:id`、`POST /exercises/:id/attempts` | 公共题目、用户提交与判分 |
| `GET /goals/:id/progress`、`GET /goals/:id/next-action` | 表现估计、规则推荐 |
| `POST /nodes/:id/lessons`、`GET /lessons/:id`、`POST /lessons/:id/events` | 按需生成、读取、交互回流 |

有模型调用的 POST 通过 AgentLoop 创建或复用 run，返回 `202 {run_id, status}`；目标澄清/图谱生成/按钮生成可以直接执行生成用例，不要求先经过 Runner。内部生成工具仍在父 run 内执行，不另起一项 API 任务。上传返回 `202 {document_id, status}`，通过文档状态读取解析结果；同步作答/确认/学习事件 ACK 等返回保存结果，解释 run 使用 sessions runs API 单独创建。输入/结果都定义 Schema，生成前验证前置业务状态。统一错误：

```json
{"error":{"code":"graph_revision_conflict","message":"路线已更新，请刷新后重新审核。","retryable":false,"run_id":null}}
```

### 11.1 运行状态

`queued → running → completed / failed / cancelled / budget_exceeded / interrupted`。

AgentLoop 是所有模型任务的统一生命周期入口，无论走 Runner 还是直接生成用例，都由其单一收束点提交终态并在当前进程发一次 terminal 事件；重连仍可通过快照看到终态，重启后的 interrupted 通过状态查询可见。文字已输出但后续失败时，文字标为 partial，不成为完整成功答案；已保存的题目或学习页仍可显示。

### 11.2 SSE 事件

信封：`{schema_version, run_id, seq, type, timestamp, payload}`。最小类型：

这些是**应用对外事件**，不是内核的事件类型。应用层接收通用内核进度，过滤私有字段、关联 run、原子分配递增 seq，并更新同一快照；表现层仅编码信封/发送 SSE。`artifact.ready` 来自应用用例已提交的产物，终态来自 AgentLoop 的单一收束点；用例不自行另发 run 终态。

- `run.snapshot`：当前进度、已输出可见文本、工具状态，用于同进程晚加入订阅。
- `run.started`、`stage.changed`。
- `message.delta`：可见回答文本，不混入 tool arguments 或隐藏推理。
- `tool.started`、`tool.finished`：调用 ID、名称、结果状态、摘要、耗时。
- `artifact.ready`：已保存的图谱草稿/题目/学习页引用。
- `run.completed`、`run.failed`、`run.cancelled`、`run.budget_exceeded`、`run.interrupted`：终态与可读摘要。

使用成熟服务端流式响应机制；心跳和代理 buffering 设置有测试。SDK 接收的流与浏览器收到的自定义 SSE 不是同一协议，不假装可以直接使用未适配的 `useChat`。

### 11.3 刷新、断开与恢复边界

- 页面关闭/连接断开不等于用户取消；已有 run 可在当前进程内继续，仍受预算限制。
- 重连只获取**当前快照与后续事件**，不提供持久化 token 级重放；订阅注册和快照序号须避免竞态/重复追加。
- 活动 run 用内存有界缓冲，终态结果落库。刷新后先 GET run，再读取已有消息/产物，不重新发 POST。
- 进程重启后通过数据库看到 `interrupted`，内存中的未保存 token 可能丢失；不能宣称完全恢复。
- 用户显式重试用 `retry_of_run_id` 创建新 run，复用原输入、root task 与用户消息；已完成写工具按稳定 operation key 复用。用户选择“重新生成”才创建新 root 与新产物版本。
- 不为了断线恢复重新引入记忆事件流、通用审计回放或分布式任务系统。

## 13. 从零实施顺序与阶段验收

建议约 4～6 周独立开发节奏，**只是规划估计，不是用户已承诺工期**。每阶段围绕一条最小可运行链路建设，不先画完所有前端，也不先造完整通用 Agent 框架。M1 的执行链只实现当前必要的 Loop/Runner 与运行契约，不预建插件、工作流或复杂调度。

### 13.1 实施依赖与验收规则

- **先有共同运行外壳，再接第一个模型业务。** 目标澄清、图谱生成和学习对话复用 M1 的 AgentLoop/gateway，不在每个场景各写任务管理后再统一。
- **当前阶段不验收未来消费者。** M4A 的资料能力只接入已存在的问答/图谱/练习；学习页 grounding 归 M4B，不要求检索阶段提前实现教学包。
- **每个阶段区分模块验收和链路验收。** 纯领域测试不依赖模型，纯内核测试不依赖业务；HTTP/SSE、持久化和场景串联另用集成/E2E 证明，不能拿一个大 E2E 替代所有模块证据。
- **功能出现时就验收失败边界。** 预算/取消随 M1，版本冲突随 M2，答案隔离/作答去重随 M3，来源失效随 M4A，解释幂等随 M4B；M5 做汇总回归，不首次补齐这些行为。
- 无 Key 时可继续 fixture 开发与确定性验收，但阶段记录须分列“离线已通过 / 真实模型待验证”。真实模型的 P0 闭环、smoke 与评估必须在最终交付前补齐，不能把离线通过说成真实验证通过。

| 阶段 | 必需前置 | 本阶段交付与验收集 |
| --- | --- | --- |
| M0 | 空项目与开发环境 | 工程入口、复用探针、初始 import 边界 |
| M1 | M0 | 最小 Loop/Runner 执行链；core/run 测试与 HTTP/SSE 集成 |
| M2 | M1 的运行契约 | 目标/图谱链路；graph/domain 测试与规划 E2E |
| M3 | M1 + M2 | 节点 Agent、练习/进度/推荐；practice 测试与 P0 E2E |
| M4A | M2 + M3 的已有消费者 | 资料/引用；documents 测试与资料增量 E2E |
| M4B | M3；资料型学习页另需 M4A | 受控学习页/解释回流；lessons 测试与学习页增量 E2E |
| M4C | M2 的图谱版本规则 + M3 的工具适配 | 图谱提案；proposal 测试与人工审核 E2E |
| M5 | M3、M4A、M4B、M4C 全部通过 | 全量回归、真实模型证据、评估与交接 |

M2 的纯领域规则可以在 M1 期间独立编写，M4C 也可在 M3 后先做；这不是要求大规模并行开发。默认仍按表顺序逐项交付，**实际依赖不等于所有模块必须互相等待**。同一预算、共用生成用例和学习页复用练习是合理运行时组合，不是需要消除的耦合。

### M0：工程入口与复用能力探针

- 初始化前后端、锁文件、SQLite 初始迁移、测试入口与 bootstrap；只创建当前需要的模块，不为最终全部实体预建空实现。
- 写最小 ADR：Loop/Runner 的职责与 Agent 功能归属、领域/内核隔离、业务持久化≠记忆、FTS 与受控组件选择。
- 做小型 fake 模型/工具协议探针，使用 `echo` / `add` 验证工具消息配对；不要求这一探针已是完整 Runner。建立 import 边界检查，app 包导入无 Web/数据库启动副作用。
- 分别验证真实模型一次 tool call、React Flow 布局、FTS5 中文检索和 PDF 文本抽取。记录来源、许可与结果；探针不是正式文档业务功能，无 Key/网络时如实列待验证。
- **模块验收**：初始依赖检查与离线探针通过，复用记录和锁文件存在。
- **链路验收**：无 Docker 原生启动、健康接口可用；Key 不进前端，fixture 标识可见。此阶段不要求目标/图谱/教学包已实现。

### M1：最小 Agent 执行链（Loop + Runner）

- 实现通用 Runner、注册表、ContextWindowManager、ExecutionControl 与 BudgetedModelGateway；SDK/fixture 适配器通过端口接入。
- 实现应用层 AgentLoop 的最小运行生命周期：request_id 去重、session/task_ref 关联、准入、预算注入、取消、消息/摘要保存与单一终态；内存任务表及 SSE 快照仍按第 11 节边界。
- 用非学习的 echo/add 场景跑通 Loop→Runner→工具→回答，同时用简单直接模型任务验证 Loop→执行用例路径。测试场景放测试/演示夹具，不给正式 Agent 增加任意执行工具或新增生产 echo API。
- **模块验收**：纯 fake 内核无需 Web/库/学习实体即可运行；完整工具协议、参数错误、上下文/次数上限、超时/取消有测试；共享 gateway 不绕过或双重计数。
- **链路验收**：通过应用测试夹具驱动实际运行查询/SSE/取消 API，验证流式可见、去重只执行一次、取消后不启动新调用、终态唯一、断开不等于取消、刷新查状态而不重发、重启将未结束 run 标 interrupted。此阶段不要求学习业务闭环。

### M2：目标、图谱与独立学习规则

- 目标输入/有限澄清/确认与图谱结构化生成复用 M1 的 Loop/gateway；实现编辑、保存、显式发布与 revision 检查，不另写临时模型任务管理。
- domain 实现图谱无环/边端点/节点时间为正等规则；用 fixture 覆盖合法、有环、错误边、非法时间和修复失败，不引入未定义的总学时硬阈值。
- 独立实现判分、掌握计算、下一步排序/时间预算的纯规则，使用普通测试数据；正式出题、作答 API 与学习 UI 归 M3。
- **模块验收**：graph/domain 确定性测试通过；判分和推荐规则无需 Loop/Runner/模型/Repository。
- **链路验收**：目标→澄清/跳过→确认→候选图谱→编辑→发布可用；生成不自动确认或发布，版本冲突不覆盖，刷新恢复路线。此阶段不要求 Agent 出题或资料上传。

### M3：节点 Agent 与练习闭环（P0 功能完成）

- 接入 LearningContextAssembler、LearningToolCatalog 与业务工具适配，复用已有 Loop/Runner，不再次建设运行外壳。

## 14. 测试与 Agent 评估要求

### 14.1 确定性自动化测试（无 Key 也必须能跑）

**内核：**纯 fake 模型 + 普通假工具，验证回答/工具回注/完整 tool ID；流式 arguments 未结束不执行；未知工具；坏 JSON；超时/取消；轮数/调用数/上下文上限；工具错误；不支持 tools；已输出后不自动整段重试。内核测试不启动 Web、数据库、SDK，不 import 学习业务。

**领域：**用普通数据验证图谱合法性、判分、掌握阈值、推荐排序/时间预算、教学包版本规则；不给模型或 Repository fake，证明规则本身无 I/O。

**应用：**注入 fake 模型与内存 Repository/检索端口，分别验证 AgentLoop 的去重/准入/预算/取消/终态和场景用例的工具选择、作用域、生成候选→领域校验→保存、引用、安全事件投影。Runner 路径和直接生成路径共用生命周期；内部生成不另起子 run。主循环 + 工具内生成 + 修复累计超过六次必须停止，且每次只计一次；未提交产物不能发 `artifact.ready`。

**架构：**用轻量 AST/import 检查或成熟 import-linter 验证第 9.3 节依赖规则，禁止核心 import 外层/彼此、应用 import infrastructure、路由直用 ORM/SDK。增加独立内核入口 smoke（app 包无启动副作用），给两个不同业务工具集合运行同一 Runner；测试失败说明分层不成立。不要为此自建复杂静态分析框架。

**业务：**草稿与发布隔离；无环验证；revision 冲突；提案生成不改图、接受才提交、拒绝无副作用；公共 DTO/消息/SSE 不泄露正式答案；重复 submission；跨 run 重试复用产物而重新生成产生新版本；按钮与工具生成同用例且无需相同入口名称去重；同题重答/完全重复题不涨统计；新题答错可降状态；节点 revision 变更使旧成绩不计当前；依赖排序和时间预算推荐；阅读不改变掌握。

**资料/组件：**中文与英文检索；空召回；未绑定资料不能读；未知/过期引用；解析失败/重启/重试；不同产物的短引用 ID 不串来源；Markdown raw HTML 不执行；不支持组件拒绝；脚本字段拒绝；教学包不得引用不同内容版本的题目；伪造成绩事件无效；重复事件去重；source_event_id/slot 的任务关联在并发、响应丢失、创建失败和换 request_id 时仍幂等，显式失败重试与重新解释按不同语义处理。另测未知 Host/Origin 无法触发本地写操作。

**分阶段 E2E（按第 13 节归属）：**

- M2 规划链路：目标→澄清/跳过→确认→图谱→编辑→发布→刷新恢复。
- M3 P0 闭环：规划链路→节点学习→出题→正式作答→进度/下一步；另测取消、刷新、模型错误可见，不要求资料与学习页。
- M4A 资料增量：上传/解析/绑定→引用问答→原文定位；验证图谱/练习 grounding 和来源失效。
- M4B 学习页增量：生成固定组件→操作/作答→事件 ACK→解释 run；验证资料型包 grounding、解释去重与版本。
- M4C 提案链路：创建提案→差异审核→接受/拒绝→冲突，不依赖资料/学习页。
- M5 完整旅程：目标→确认→图谱→发布→节点学习→上传/绑定资料→引用问答→学习页操作→正式作答→进度/下一步，并汇总提案与异常路径回归。

fixture 固定且来源醒目，不把测试随机性混进 CI。每个阶段提交实际命令、结果和失败记录；M5 汇总已有测试证据，不将未来 E2E 当作早期阶段的前置验收。

### 14.2 小型评估集

先构建不少于 20 个可版本管理的案例，每例有输入、资料/前置状态、期望工具/产物、允许结果与禁止行为。覆盖：

- 5 例工具选择/不需要工具/多步任务。
- 5 例资料可回答、不可回答、中英文、错误引用和来源过期。
- 5 例图谱生成校验与需要用户确认的提案。
- 5 例练习、推荐、交互事件、取消/预算失败等边界。

fixture suite 用来验证协议与业务，真实模型 evaluation 用来验证模型表现，**两者分别报告**。记录模型 ID、配置、提示词版本、数据集版本、日期和失败样例，不宣称一次跑通就是稳定性保证。

### 14.3 最少报告指标

| 指标 | 定义/注意事项 |
| --- | --- |
| 任务成功率 | 满足案例验收条件的任务数/全部案例；取消/预算耗尽单独列出 |
| 工具选择正确率 | 该用且用了期望工具，及不该用时没有乱用；允许替代策略需预先定义 |

| token 与成本 | 有真实 usage 才汇总；估算/未知分开，不拿估算当供应商账单 |

确定性用例应全通过；真实模型结果必须如实记录，不预设“95% 成功率”等简历数字。若尚未取得 Key，只能验收离线部分，M5 的真实模型验收应标记 blocked，不能用 fixture 充数。

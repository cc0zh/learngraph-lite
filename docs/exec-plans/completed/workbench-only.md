# 单一学习工作台：入口收敛，保留业务能力

## 目标、范围与风险

- 用户选择只保留学习工作台，整合现有能力而不是删除资料、推荐、提案或人工编辑。
- 唯一业务界面为 `/`：原文、资料管理、图谱管理均在工作台主区内打开；URL 保存当前工具、目标和原会话，返回不丢范围。
- 旧 `/library`、`/goals/:id/plan|learn`、`/documents[/:id]` 只做只读兼容定位，不再渲染第二套页面。旧 session、成绩、教材、题目、run 和后端 API 不删除。

- 不升级依赖、不调用真实模型、不读密钥、不动日常数据库，不扩大到 AI 质量或后端事务重构。
- 现有工作树有大量用户改动，增量修改，不重置。测试使用新临时 SQLite 与独立端口。
- 基线调查：Python runner 236 通过；Node 24/25（源码归档 README 命名断言）；前端 build 通过；E2E 77/78，资料解绑单项复测通过。不能把这些旧结果写成本任务验收。

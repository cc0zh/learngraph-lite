# 用户输入真实性与验收口径审查

## 目标与边界

- 用户指出真实 P0 通过“务必调用 create_exercise 工具”等实现级提示，不能代表真实用户行为，要求检查类似问题。
- 审查真实浏览器输入、其他模型 smoke/demo/eval 的证据性质、前端自动发言和用户可见工具状态。系统/开发指令可以描述工具，工具断言可以核查内部名字；不能把这些要求伪装成用户问题。
- 只改有明确证据的测试输入、断言/文案及验收描述，不重做教学或规划策略，不修改日常数据、依赖或并行文档改动。
- 本轮不调用真实模型，不把 fixture 的通过当作自然语言工具路由成功，也不重写上轮原始真实证据。

## 步骤与验收

- [x] 定位强制工具名、流程引导、安全条件提示和过度推论，区分协议测试与产品旅程。
- [x] 将产品旅程改为自然表达，保留实际持久产物、显式确认/发布和真实工具活动断言。
- [x] 补离线测试防止把内部指令重新写回真实用户输入，并验证受影响 UI。
- [x] 更正当前质量结论，记录未复测的自然意图路由与默认答案保护；运行相关检查。

## 初步发现

- `frontend/real-tests/p0.spec.ts` 的节点问题指定 create_exercise 和不披露答案；目标输入指定草稿、不得确认/发布及“真实验收”标签，存在向被测模型泄露测试期待的问题。
- `frontend/tests/p0.spec.ts`、`recovery.spec.ts` 也有“调用工具”式模拟输入；fixture 只验证确定性业务/恢复，不证明自主工具选择。
- `Workbench.startLearning` 默认发送普通主题介绍要求，没有工具名，不应为本任务重写该正常路径。
- 并行工作树包含文档站/核心机制资料，以及上一轮真实测试修正和记录；保留所有既有改动。

## 审查结果与改动

1. 浏览器真实目标输入含草稿/禁止确认发布/验收标记，教学问题强制 create_exercise 且提醒保密。现集中到 `frontend/real-tests/user-inputs.json`：目标只写背景、主题、时间和偏好，问题只请求短例子与单选练习。
2. `scripts/run-real-p0-smoke.py` 也存在工具名、执行顺序、count/purpose 及排除其他工具的用户指令；已改为同一自然出题需求。此 HTTP 流仍是直接 API 驱动，不冒充完整工作台对话验收。
3. 浏览器旧断言只看工具名、任务完成和第一道题可见，可能把首次教学已有题目当本轮出题。现按本轮 run 断言 create_exercise completed、前后 ID 集合恰好新增一道、本轮输出与保存 ID 对应、公开题目无答案字段；不直接读私有答案帮助选题。
4. 目标/发布边界改由只读状态断言负责：显式确认前 confirmed=false 且无图谱、发布前 graph=draft；另核查实际规划工具成功，移除“small graph”等超过原数量范围断言的成功命名。语义范围、依赖必要性和自然语言泄漏仍需人工评估。
5. `components.tsx` 原来只翻译 planning 工具，teaching 直接显示协议名。现所有已注册业务工具用中文动作名，未知工具用通用文案；原名保留 `data-tool-name` 及公共 run 诊断，既不删可观测性，也不让普通用户理解实现名。没有尝试过滤模型自由回复中的所有英文或技术词。
6. 离线 P0、恢复和提案旅程去掉“调用工具/不要接受”式期待提示，保留待审核、拒绝后状态/成绩不变等断言。fixture 仍按预设规则行动，不升级为真实自然路由证据。
7. `smoke:real` 的 echo 要求属于有意的供应商协议测试，未误删。学习资料 demo 的 completed 不等于引用/推荐合格，输出新增 quality_assessed=false 和 scope，文档明确边界；未扩展此 demo 为质量评估平台。

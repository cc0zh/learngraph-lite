# Agent 主导的目标与图谱规划

## 目标与范围

- 将默认规划入口从固定三题向导改为连续规划对话：Agent 提取已知信息、按需发问、提出目标草稿、生成与调整路线，并解释依据和取舍。
- 问题、目标审核和路线审核使用固定安全组件；用户明确确认目标并授权后，由 Agent 推进图谱生成。模型没有确认或发布工具。
- 复用 AgentRunner、预算、SQLite run/协议历史、SSE、现有目标确认/图谱发布与版本保护；保留手动规划作为可选兼容入口。
- 不引入多 Agent、联网、沙箱、自定义 HTML 或新依赖；不调用付费模型验证。fixture 只证明交互与契约，不代表真实生成质量。

## 实施步骤与验收

  - 检查：原生工具协议配对、无模型确认/发布能力、版本冲突/取消/重试、结构化回答校验、SQLite 重开恢复。

  - 检查：清晰输入不重复固定问卷、按需选项/自定义/跳过、解释不改路线、反馈显示差异、明确发布、失联与旧卡安全。

## 关键决定

- 专用规划 Agent 而非固定问卷换皮；当前目标/路线是领域事实，对话是协作记录。
- 每个问题卡答案保留原问题标识；旧卡和旧版本不能静默改写当前目标。发问后运行完成，不占并发等待用户。
- 图谱节点数量由 Agent 根据目标和投入决定；旧直接生成 API 保持兼容。路线差异由代码计算，解释由 Agent 提供。
- 确认仍走确定性 HTTP API；Agent 仅提草稿。确认后的生成是用户“确认并生成”操作授权的下一次请求，失败后显式恢复，不靠刷新自动续跑。

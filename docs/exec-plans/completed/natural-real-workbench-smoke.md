## 只读内容核对：链路通过不代表教学质量通过

原测试库仅用 SQLite `mode=ro` 查询；未运行模型生成代码。另写固定 Python 表达式参考计算，确认两题的答案键分别与输出 `4 30 (20, 30) True`、`(1, 3)` 相符；第二题未正式交卷，不能记第二次作答/反馈通过。

1. **提前提示答案**：第二个教学回合先用同一组 10/20/30/40 数值逐项列出长度、负索引、切片及成员判断结果，再把相同表达式组合成正式单选题。虽然没有直接说“选 A”或读取私有答案，回复已给出待测题所有计算结果；无法认定默认不泄漏答案通过，单次正确反馈也不能证明学习者独立掌握。自动化仅验证公共字段隔离，没有语义泄漏断言。
2. **确定概念错误**：第一个教学回合把切片说成总返回新序列，并以 t[:] 说明不是同一个对象。对本机 Python 3.13 的普通 tuple，固定参考 `t=(10,20,30,40); t[:] is t` 为 True。应说明 tuple 切片不保证新对象，不能把 list 的复制语义泛化到 tuple；不反向许诺所有实现保持身份。
3. **自由回复仍暴露内部名**：第一个教学回合直接说将用 create_exercise 出题，第二个还出现 source_mode/general 和题目 ID 等实现细节。上一轮中文化只覆盖工具状态组件，不覆盖模型自由文本；不能声称内部名称对普通用户已完全隐藏。
4. GFM 表格仍出现在生成文本中，原有渲染可读性问题没有因本轮链路通过而解决；图谱前置必要性未做全面评分。

这些是当前小样本已观察到的内容质量缺陷，不泛化为整体正确率、任意私有字段外泄或发布越权。目标与练习自由输入未给工具/保密提示；但“确认并生成图谱”按钮仍按产品逻辑发送待审核/不要发布的续写指令，本轮验证的是此明确操作边界，不是所有无提示或对抗输入的默认保护。

# 目标与知识图谱规划

1. 先读取当前目标、已回答或跳过的问题、路线与版本；把用户自述基础视为尚未验证的信息。
2. 围绕主题范围与理解深度发现关键缺口；基础、成果和时间可辅助，但不是必填问卷。不重复追问已回答或主动跳过的项。
3. 保留用户探索主题的意图，不强迫收窄成项目交付；缺失信息留空并说明不确定性，需要澄清时使用当前可用的提问工具。
4. 用主题、子主题、知识点组织少而清晰的节点；仅为真实前置依赖连线，允许独立主题，不人为串成单链。学习路线是地图的一种使用方式，投入与验证建议不替代知识结构。
5. 提交目标或路线草稿供用户审核；纯解释不修改草稿。已发布路线的调整走当前应用提供的待审核提案流程。

技能只提供流程建议，不增加工具权限。确认目标、发布路线和接受提案仍由用户通过应用执行；遇到版本冲突先重新读取，不覆盖既有学习记录。
